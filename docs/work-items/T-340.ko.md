# T-340. 모노레포 등록의 의존성 근거 검색

[English](T-340.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-005, T-320

## 설계

개별 연결을 조사하기 전에 읽기 전용 검색으로 JVM·Spring의 공통 단서를 모은다. 레포에서 반복되는 클라이언트 패턴을 같은 검색에 추가할 수 있게 한다. 호출 코드, 선택한 실행 설정, 제공자의 근거가 일치할 때 연결을 레지스트리에 반영한다.

쇼핑몰 데모와 제공자가 모호한 사례, 제외 경로, 사내 래퍼를 포함한 임시 예제로 확인한다. 설치본과 링크도 검증한다.

## 개발

- Python 검색 도구가 지정한 Java·Kotlin·YAML·properties 파일의 상대 경로, 줄 번호, 규칙을 출력한다. 레포별 클라이언트를 찾을 때는 검색 규칙을 추가할 수 있다.
- 영문·한국어 스킬과 탐색 가이드가 검색을 먼저 실행하고 호출 코드, 선택한 설정, 제공자를 이어서 추적하도록 정리했다. 초안 프로토콜에 검색 범위, 추가 규칙, 남은 후보, 다음 확인 항목을 기록한다.

## 검증

- Windows 쇼핑몰 데모에서 공통 HTTP 래퍼 규칙으로 서비스 간 호출 여섯 곳을 찾고 소스에서 실제 대상을 확인했다. DB 래퍼는 연결 후보로 잡혔고, PostgreSQL 인스턴스 두 곳은 적용 설정을 확인할 때까지 후보로 남았다.
- 임시 예제로 범위 제한, 중첩 범위의 중복 제거, Java·Kotlin 검색, 빌드·테스트 경로 제외, 정확한 줄 번호, 설정값 제외와 입력 파일 유지 여부를 확인했다. 기존 등록 회귀 테스트 네 개도 통과했다.
- 스킬 형식과 상대 경로를 검증했다. Windows 설치본에 반영한 파일 일곱 개의 일치를 확인했고, 설치된 검색 도구로 Orders의 HTTP 호출 두 곳을 찾았다.

## 재개 지점

실제 업무 앱에 [의존성 검색](../../skills/injector-register-monorepo/references/monorepo-initialization.ko.md#2-의존성-후보-검색)을 적용한다. 기존 수동 등록과 조사 시간 및 미확인 항목을 비교한다.
