# T-300. 실행과 비교 리뷰 수정

[English](T-300.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-260, T-290

## 설계

기본 레지스트리의 실행 세션 경로를 통합하고 기존 세션을 정리할 수 있게 한다. 실행 전에 Compose 공개 포트를 검사하고 관리 프로세스가 종료되면 제한된 진단 출력을 로컬에 남긴다. 지정한 쿼리 값을 비교하고 JSON Pointer 제외는 원본 배열 인덱스를 기준으로 적용한다.

리뷰에서 찾은 다섯 가지 문제의 회귀 테스트와 실제 쇼핑몰 데모 실행을 완료 기준으로 삼는다.

## 개발

- 소스의 기본 레지스트리는 경로를 직접 지정해도 같은 실행 잠금과 세션을 사용한다. 종료 시 이전 경로의 세션도 찾는다. 명시적 레지스트리로 생성한 기존 IDE 구성 경로는 유지한다.
- 실행 검사에서 등록된 호스트 포트와 전송 프로토콜을 선택된 Compose 서비스와 대조한다. 프로세스 종료 오류는 노드와 최대 64 KiB의 출력을 담은 로컬 파일 경로를 알려준다.
- HTTP 관측은 `requestQuery`로 지정한 키를 수집하며, 쿼리 설정 없이 쿼리 값이 오면 불완전으로 처리한다. Verifier는 중복 제외를 제거하고 원본 배열 인덱스를 기준으로 제외를 적용한다.

## 검증

- Windows에서 런타임과 HTTP 관측 회귀 테스트가 통과했다. 임시 Docker Compose 설정으로 잘못된 공개 포트는 검사와 실행 준비 단계에서 거부되고 일치하는 포트는 통과하는 것을 확인했다. 쇼핑몰 통합 테스트는 `real`과 `mock`에서 통과했다.
- Node 웹 테스트, Verifier 동작 테스트, Spring 기준 기록과 재비교가 통과했다. Linux 컨테이너에서 POSIX 실행기의 진단 출력 제한과 파일 권한을 확인했다. macOS에서 직접 실행하는 검증은 남아 있다.
- 기본 Python 테스트 133개가 통과했고 별도 실행이 필요한 7개는 건너뛰었다. 데모 레지스트리 세 개가 모두 검증을 통과했다.
