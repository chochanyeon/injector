# T-280. 쇼핑몰 데모의 Vault·로그 연동

[English](T-280.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-270

## 설계

WireMock이 서비스별 Vault KV v2 설정을 제공한다. 루프백 Loki에 구조화 로그를 모으고 HTTP와 Kafka로 같은 요청 ID를 전달한다.

두 프로필에서 인프라가 준비되고, 같은 Vault 키로 서로 다른 Redis 만료 시간이 적용되며, Loki 쿼리 하나로 주문의 HTTP 호출과 Kafka 소비를 확인하면 완료다.

## 개발

- 데모 Compose, 레지스트리와 노드 파일이 Vault와 Loki를 선언하고 JVM 실행 환경에 호스트 주소를 주입한다. Vault 경로마다 WireMock 응답 파일을 둔다.
- 공통 Java 라이브러리가 시작 시 Vault 설정을 읽고 HTTP 요청 ID를 전달하며 구조화 로그를 Loki에 전송한다. Orders가 같은 ID를 Kafka 헤더에 넣어서 Notifications가 배송 상태를 저장할 때도 기록한다.
- 데모 가이드에 포트, 예제 설정, macOS 셸과 PowerShell의 주문 로그 조회 명령을 추가했다. 로그 전송은 비동기로 진행하고 동시 전송 수를 제한한다. 로그는 데모 세션 동안 유지된다.

## 검증

- 레지스트리 검증과 주문 실행 계획이 통과했다. `real`은 12개, `mock`은 11개 노드를 준비한다. Docker Compose에서 두 인프라가 확인됐고 Loki 이미지가 설정 파일을 읽었다.
- Windows에서 Docker Desktop과 JDK 25로 `installDist`와 `test_shop_demo.py` 통합 테스트를 실행했다. 두 프로필의 실제 주문, Vault 조회 및 거절, 서비스별 Redis 만료 시간, 같은 요청 ID의 HTTP 호출과 Kafka 배송 로그 조회를 확인했다.
- 기본 Python 테스트 129개가 통과했고 별도 실행이 필요한 7개는 건너뛰었다. 데모 문서에 macOS 셸 명령도 포함했다. 실제 실행 검증은 Windows에서 진행했다.
