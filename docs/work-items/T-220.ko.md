# T-220. Registry 실행 조건 검사

[English](T-220.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-060, T-150, T-200

## 1. 설계

선택한 소스 워크트리, registry, 앱, 프로필, variant를 기준으로 버튼을 눌러 검사한다. 의존성 계획과 그 계획에 포함된 노드의 실행 준비 규칙을 재사용한다. 첫 번째 문제를 표시하고 설정값은 응답에 포함하지 않는다. Compose 구성을 읽을 수 있으며 서비스를 시작하거나 종료하거나 실행 파일을 생성하지 않는다. Registry에 기록되지 않은 요구사항의 누락이나 실제 앱 기동 여부는 확인할 수 없다.

## 2. 개발

실행 화면이 현재 선택을 토큰으로 보호된 `/api/check`에 보낸다. 선택을 바꾸면 결과를 지운다. 실행 준비와 검사가 설정 해석, 실행 방식 검증, 메모리 내 IntelliJ 실행 구성 생성을 공유한다. 호스트 이름 해석, 포트 소유권, 실제 서비스 응답 여부는 실행 준비에서 확인한다.

## 3. 검증

HTTP 회귀 테스트는 유효한 선택, 계획은 가능하지만 준비를 막는 의존성 variant, healthcheck가 빠진 Compose 서비스, 토큰 검사, 런타임 파일이 생성되지 않는 동작을 다룬다. Compose 호출을 모의 처리해 `config`만 호출되는지 확인했다. 테스트 DOM에서 성공, 오류, 워크트리 변경 후 이전 결과 무시를 확인했다.

Windows에서 전체 115개 테스트 중 109개가 통과했고 선택 실행 항목 6개를 건너뛰었다. 설치된 Docker Compose CLI로 데모의 `dummy`와 `real` 프로필 검사도 통과했다. 화면 조작은 테스트 DOM에서 확인했다.

## 4. 재개 지점

웹이나 [T-320 CLI](T-320.ko.md)에서 실제 등록한 업무 프로젝트를 검사한다. 등록되지 않은 요구사항은 소스 분석을 포함하는 초기 등록 과정에서 찾는다.
