# T-230. Fix execution and validation issues found in review

**English** · [한국어](T-230.ko.md)

[Work index](../index.md) · Prerequisites T-090, T-150, and T-220

## 1. Design

Both Compose commands use the resolved node environment. Reject required Compose services outside the selected node's registry dependency graph because startup uses `--no-deps`. Share cycle checks between CLI and editor validation. An IntelliJ check reports the registered module and main class for IDE confirmation because Injector cannot establish the imported module's classpath. Resume polling after a status request fails without sending another prepare request.

## 2. Development

Compose gathers reachable service identities in dependency order. Missing required services stop preflight before resources change. Optional dependencies may be absent. Configuration and startup reuse the same environment, and generated overrides contain variable references. CLI `validate` checks cycles in all profiles or the selected profile. The web UI reports IntelliJ confirmation separately and retries status reads after a transient failure.

## 3. Verification

On Windows, 110 Python tests passed and six opt-in integration tests were skipped. Both tests in `node --test tests/test_web_app.js` passed. The installed Compose CLI resolved registry-only variables, preserved literal values in serialized configuration, rejected the missing database through preflight, and checked demo `dummy` and `real` plans. The regression test compares the environments passed to mocked Compose configuration and startup. No containers were started for this item.

## 4. Resume point

Confirm the imported module and main class with an actual macOS IntelliJ Debug session during the multi-app integration check.
