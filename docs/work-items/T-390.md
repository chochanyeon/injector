# T-390 · Build and run the full test environment

**English** · [한국어](T-390.ko.md) · [Work index](../index.md)

## Design

Provide one non-interactive command to build the fixtures, start live dependencies, and run Python, browser JavaScript, and Verifier JVM tests. Enable every opt-in Python integration test and run the shop fix suite through the CLI. A skipped Python test blocks a passing result on the supported platforms. Preserve progress logs, exit status, and links to evidence. Scope temporary resources to the run and clean them up when the tests finish.

## Development

- Add the standard-library [environment runner](../../verifier/verify_environment.py). It creates a fresh Python virtual environment, installs pinned dependencies, builds the Spring probe and shop distributions, and starts WireMock Vault on a dynamically assigned loopback port.
- The runner invokes the Python discovery suite with the live integrations enabled, the Node.js tests, both local JVM test modes, and the Verifier Git worktree integration script. It writes per-stage logs and a versioned JSON result.
- Add an integration test that runs the real shop fix suite through `injector.py`. It retains both scenarios and all four worktree observations when invoked by the environment runner. It uses the same isolated ports and cleanup as the existing shop tests.
- On macOS the runner uses the same [launcher check](../../tests/check_macos_launcher.sh) as CI.
- Update [runtime cleanup](../../injector_core/runtime.py) to wait for the recorded Windows process after terminating its job. A Python virtual-environment launcher can remain outside the job until its child exits.

## Verification

- Windows preflight tests verified that a missing executable produces a saved failure and an existing evidence directory remains intact.
- Spring Boot and the shop distributions built from exported source with no build output. Both the checkout path and the Maven path contained spaces.
- The fresh Windows virtual environment reproduced a working-directory lock after IntelliJ session cleanup. The original test passed three consecutive times in the same environment after the runtime fix.
- A fresh Windows Git checkout ran the final command with a new Python environment and no prior checkout build output. All 13 stages passed, with exit code 0. This included 150 Python tests, six Node.js tests, the seven JVM tests in record and verify modes, and six Git worktree integration cases. No tests were skipped in the final Windows run.
- The live shop suite passed fix verification and the rejected checkout regression. Its report retained four recordings. The run removed the temporary containers and networks.
- The launcher script passed shell syntax validation. The complete environment still needs a run on native macOS.

## Resume point

Use `python verifier/verify_environment.py` for the full test run. Verify the same command on native macOS. Use [T-380](T-380.md) for automation against a registered target project.
