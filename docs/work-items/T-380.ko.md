# T-380 · 입력 대기 없는 등록·검증 자동화

**[English](T-380.md)** · 한국어 · [작업 인덱스](../index.ko.md)

## 설계

LLM이 검토된 레지스트리, 시나리오의 기대 동작, 워크트리 경로를 사용해 CLI에서 로컬 검증을 끝낸다. 최초 등록에서는 코드 근거를 수집하고 누락된 설정이나 검토할 결정을 표시한다. 반복 실행은 승인된 입력으로 사전 점검, 앱과 의존성 기동, 실패 재현, 후보와 관련 동작 검증, 자원 정리까지 수행한다. 웹 화면도 같은 검증·실행 로직을 사용한다.

- 사전 점검은 앱을 시작하기 전에 모든 항목을 확인한다. 대상 시나리오나 노드, 누락된 입력 또는 실패한 검사 항목을 구조화해 반환한다.
- 실행은 판정, 종료 코드, 증거 파일 경로와 함께 입력 오류·기동 실패·동작 차이·정리 실패를 구분한 버전 있는 결과를 남긴다. LLM은 이 결과로 다음 조치를 판단할 수 있다.
- 새 에이전트가 저장소 문서에 있는 조건에 따라 쇼핑몰 워크트리 두 개를 준비하고, 화면 조작 없이 같은 보고서를 생성할 수 있다. 기대하는 업무 동작과 필요한 비밀 값은 검토된 입력을 사용한다.

## 개발

의존성 근거 검색, 등록 초안 검증·변환, `check`, `verify-suite`가 구현되어 있다. `verify-suite`는 준비된 워크트리를 받아 JSON과 Markdown 증거를 남긴다. 현재 스위트 사전 점검은 실행 명령 안에서 이루어진다. 잘못된 입력은 JSON 결과 없이 텍스트 오류로 반환될 수 있다. 데모 빌드는 별도 단계다. [등록 절차](T-340.ko.md) · [스위트 실행](T-360.ko.md)

## 검증

예정. 올바른 스위트, 후순위 시나리오의 입력 오류, 기동 실패, 확인된 회귀, 수정 성공을 점검한다. 에이전트가 결과 파일과 종료 코드로 다음 조치를 판단할 수 있는지 확인한다. Windows와 macOS에서 실행한다.

## 재개 지점

기존 스위트 사전 점검을 상태를 변경하지 않는 명령으로 제공하고 결과를 구조화한다. 실행 명령도 같은 사전 점검을 사용한다. 결과 형식을 검증한 후 화면 조작 없이 실행하는 절차를 문서화한다.
