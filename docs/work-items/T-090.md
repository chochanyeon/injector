## 1. Design

Related to [design](../design.md) section 9 and D-06–D-08. Identify resources created by failed runs and preserve foreign resources. Define sharing, conflicts, reprepare, reverse cleanup, and explicit data reset. Preflight the executable, IDE artifacts, and TCP endpoints. Allow listeners owned by the prior session. Preserve the prior session and config on preflight failure and recheck ports after stopping it. Publish XML and YAML after readiness. A failure after switching cleans new resources and preserves previous IDE files. Restarting already stopped resources remains open.

Windows uses a named Job Object, and macOS uses an isolated process group. Register self-detaching daemons as Compose or external. Resolve explicit commands against `workingDirectory` and bare names against startup `PATH` and Windows `PATHEXT`. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## 3. Verification

Windows passed 107 tests including Vault and Spring Boot. Regression tests covered port conflicts, stale XML/YAML preservation, exited launchers, and module paths with spaces. All 16 runtime tests passed on Linux Python 3.10. Separate Windows CLI prepare and stop verified process persistence and cleanup. An isolated Windows demo verified same-port Compose reprepare, real Java with generated arguments, a WireMock call, and container shutdown. Direct macOS startup, IntelliJ Debug, and a work monorepo remain pending.
