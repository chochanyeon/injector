# T-420 · Registry 편집기 자동완성

**[English](T-420.md)** · 한국어 · [작업 인덱스](../index.ko.md)

## 설계

- 선택한 Registry 기준으로 아직 등록하지 않은 노드 JSON을 찾고, 선택한 상대 경로를 루트 초안의 `nodeFiles`에 추가한다.
- 분리된 노드 파일에서 스키마에 맞는 실행 필드, 등록된 의존 노드, 선택한 variant의 의존 노드에서 가져올 주입 대상을 제안한다.
- 변경은 초안에 반영한다. 나머지 JSON을 보존하고, 기존 텍스트 복구 및 리비전 확인이 포함된 검증·저장 흐름을 사용한다.

## 개발

- 로컬 토큰을 확인하는 [후보 조회·반영 코드](../../injector_core/registry_completion.py)가 선택한 Registry의 스키마를 사용한다. 루트 검색은 Registry 폴더 안에서 숨김 폴더, 빌드 폴더, 링크된 폴더를 건너뛰며 후보의 노드 스키마를 확인한다.
- [편집 폼](../../injector_core/web/index.html)은 선택한 필드만 바꾼다. 서버는 그 밖의 JSON을 그대로 유지하므로 Spring 설정의 숫자 표현도 보존한다. 저장 시에는 기존 리비전 확인과 통합 Registry 검증을 거친다.

## 검증

- Windows 데스크톱 Chrome에서 별도 Registry 파일에 신규 노드 파일을 등록했다. 의존 서비스와 Vault 포트 주입을 추가하고 IntelliJ 메인 클래스도 수정했다. 저장 버튼을 누른 뒤에만 디스크가 갱신되는 것을 확인했다.
- 웹 API 테스트에서 토큰 검사, Registry 경로 범위, 잘못되거나 중복된 후보, 분리형·인라인 노드, 스키마별 주입 방식, 수정 대상 밖 숫자의 원문 보존을 검증했다.
- Windows에서 Python 테스트 147개와 JavaScript 테스트 8개가 통과했다. 선택 실행 항목인 Shop 및 WireMock 통합 테스트 8개는 건너뛰었다.

## 재개 지점

노드 폼에서 기존 주입 규칙을 확인하고 환경 변수, JVM, Spring 설정과 프로필별 덮어쓰기를 편집한다.
