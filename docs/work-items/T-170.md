# T-170. 로컬 registry.json 편집기

[작업 인덱스](../index.md) · 선행: T-020, T-040, T-150, T-160

## 1. 설계

화면에서 선택한 프로젝트의 기존 registry.json을 열고 수정한다. 문법 오류가 있는 파일도 원문을 열 수 있어야 한다. 검증은 CLI와 같은 JSON 파서, 스키마, 참조 검사를 사용하고 각 프로필의 등록 대상에서 시작하는 DFS 계획으로 순환도 확인한다. 검증과 저장은 앱을 실행하지 않는다.

문법 오류에는 줄과 열을 표시하고 스키마·참조 오류에는 경로나 관계를 알려준다. 저장 직전에 다시 검증한다. 파일을 열었을 때의 해시가 바뀌었으면 사용자에게 최신 내용을 다시 읽도록 안내한다. 로컬 제어 토큰으로 파일 읽기와 쓰기 요청을 확인한다.

## 2. 개발

- 프로젝트 선택 카드에서 모달 편집기를 열고 검증, 저장, 다시 읽기를 할 수 있다. 접으면 같은 프로젝트에서 초안을 이어서 읽을 수 있다. 닫기와 Esc는 변경이 있을 때 버릴지 확인한다.
- 편집 API는 프로젝트 루트의 기존 일반 파일인 registry.json만 처리한다. 파일은 UTF-8과 2 MiB까지 지원한다.
- 저장은 작업 잠금 하에 같은 폴더의 임시 파일을 교체한다. 기존 권한 모드와 CRLF 줄바꿈을 보존한다. 외부 변경 검사가 실패하면 원본을 유지한다.
- 검증에 성공해 저장하면 앱·프로필 목록과 실행 순서를 다시 읽는다.

## 3. 검증

- HTTP 테스트에서 깨진 파일 열기·복구, 문법 오류 줄·열, 스키마·참조·순환 오류, 검증만 실행한 경우의 원본 보존, 저장 후 목록 갱신, 다른 편집기의 변경 보호, 제어 토큰 검사를 확인했다.
- JavaScript 구문 검사를 통과했다. DOM 테스트 대역을 실제 로컬 HTTP API와 연결해 편집 버튼, 문법 오류 위치 선택, 저장과 목록 갱신을 확인했다.
- 변경 커밋 `89e39dd`의 macOS 15 ARM64와 Windows 2025 x64 CI가 모두 통과했다. 각 OS에서 테스트 93개 통과, 외부 통합 6개 건너뜀. [CI 실행 결과](https://github.com/chochanyeon/injector/actions/runs/44191125664)
- 모달 변경에서 DOM 테스트 대역과 실제 로컬 API로 열기·접기·재열기, 읽기 재요청 없이 초안 복구, Esc 취소·확인, 오류 위치 이동을 확인했다. 웹 테스트 11개가 통과했다.
- 브라우저 제어 연결 장애로 실제 브라우저 화면에서의 클릭과 배치는 확인하지 못했다.

## 4. 재개 지점

브라우저에서 큰 registry 파일과 좁은 화면을 확인한다. 실제 실행은 기존 준비 버튼과 CLI에서 이어간다.
