# T-200. Separate registry storage from source worktrees

## 1. Design

Store local registries under Injector's Git-ignored `registries/<repo-id>/`. Worktrees can share registry settings. `--project` selects source and `--registry` selects the registry directory. Resolve `nodeFiles` against registry storage and execution paths against source. The source-root layout remains supported. External mode saves generated files under a worktree-specific path in registry storage. Import the generated XML into IntelliJ. The running app and IDE manage their own writes.

## 2. Development

The source picker accepts a folder. The registry picker selects an existing `registry.json` file. The browser displays its path and uses the parent directory for the runtime and editor. Typed registry directories remain supported. Loading checks registry validity. The UI suggests centrally stored registries and uses the same source–registry pair in the editor, plan, graph, prepare, and stop. Updated the installed registration workflow to keep settings and investigations centrally.

## 3. Verification

HTTP checked selecting a registry-free worktree and using a separate registry in the editor and graph. Runtime tests started and stopped dependencies and verified that XML, YAML, and session state stayed outside source. Windows passed 113 tests with Spring Boot and Vault integrations. CLI `validate`, `plan`, and `stop` passed with separate paths. DOM tested folder selection and the selected pair in the graph and editor. Skill format and local file hashes passed.

The file-picker fix passed 16 HTTP tests. Covered picker cancellation, rejection of other files and directories, and loading, graphing, and editing the selected registry. A headless DOM check verified path display and reload after save. Mocked launcher calls checked file and folder dispatch on Windows and macOS. Direct desktop interaction remains pending.
