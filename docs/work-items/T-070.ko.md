# T-070. 사용자 정의 호스트 이름 연결

[English](T-070.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업: T-030, T-060 · macOS 확장: [T-160](T-160.ko.md)

| 설계 | 개발 | 검증 |
|---|---|---|
| 완료(Windows hosts 범위) | 완료 | 부분 검증(관리자 시스템 파일 적용 남음) |

## 1. 설계

- 기존 registry의 `nameMappings`를 사용한다. `hosts`는 사용자 정의 DNS 이름과 루프백 IP를 등록한다. `external`은 OS에서 이미 해석 가능한 이름과 기대 IP를 선언한다.
- Windows 로컬 개발을 기준으로 `hosts preview/apply/remove`를 분리한다. 프로젝트 경로에 연결된 표시를 추가하고, 같은 IP의 수동 항목은 재사용한다. 다른 IP나 다른 Injector 프로젝트의 항목과 충돌하면 변경을 거부한다. 복원은 이 프로젝트가 표시한 행을 찾아 제거하며 registry가 이동·변경돼도 원래 경로를 지정하면 제거할 수 있다.
- hosts는 시스템 전체에서 공유하므로 apply/remove는 관리자 터미널에서 실행한다. 브라우저 및 prepare 경로는 조회만 한다. POSIX의 기존 hosts/DNS도 읽고 검증할 수 있다. 컨테이너는 별도 이름 공간이므로 Compose에서 서비스 이름이나 extra_hosts를 관리한다.
- 대상 DFS 그래프의 host 접속점에 연결된 매핑만 prepare 시작 시 확인한다. OS가 지정 IP만 반환할 때 준비를 진행한다. 잘못된 매핑에서 기존 세션 종료나 구성 파일 생성이 일어나지 않아야 한다.

## 2. 개발

- `injector_core/hostnames.py`에서 주소·이름 검증, 변경 계획, 기존 항목 보존, Windows 적용·복원을 구현했다. 원본 DACL을 보존하는 ReplaceFileW를 사용하며 기존 파일이 달라졌는지 교체 직전에 다시 읽는다. Injector 변경끼리는 파일 잠금으로 동시에 한 건만 처리한다. [Windows ReplaceFileW 문서](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)
- `registry.py`에서 선언을 검사하고 `runtime.py`에서 선택된 접속점의 이름 해석을 사전 확인한다. `injector.py`에 hosts CLI를 연결했다.

## 3. 검증

- Windows의 실제 시스템 hosts를 대상으로 `python injector.py hosts preview --project examples/registry`를 실행해 두 개의 추가 예정 행을 확인했다.
- 임시 Windows hosts에서 preview→apply→재적용→remove를 검증했다. 기존 BOM·개행·수동 수정 보존, 일치 항목 재사용, 다른 프로젝트/다른 IP 충돌, 잘못된 IP·이름 거부, 불일치 시 이전 세션 보존을 테스트했다.
- JVM에 임시 hosts 파일을 지정하고 `catalog.injector.test`를 통해 실제 WireMock 응답을 받았다. 이 파일을 바이트 단위로 복원했다.
- 관리자 권한이 없는 세션에서 시스템 hosts 변경은 수행하지 않았다. 따라서 네이티브 OS resolver의 시스템 파일 반영은 남아 있다.

## 4. 재개 지점

- 관리자 Windows 환경에서 테스트 전용 이름으로 시스템 apply→OS 해석과 호출→remove를 검증한다.
