# T-230. 리뷰에서 확인한 실행 및 검증 문제 수정

[English](T-230.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-090, T-150, T-220

## 1. 설계

Compose 검사와 실행에 노드의 해석된 환경을 공통으로 전달한다. `--no-deps`로 실행하므로 선택한 노드의 Registry 의존성 그래프에 필수 Compose 서비스가 빠져 있으면 오류를 표시한다. CLI와 편집기가 같은 방식으로 순환을 확인한다. Injector에서 가져온 모듈의 클래스패스를 확정할 수 없으므로 IntelliJ 검사 결과에 IDE에서 확인할 모듈과 메인 클래스를 표시한다. 상태 조회 실패 후에는 준비 요청을 다시 보내지 않고 조회를 재시도한다.

## 2. 개발

Compose 서비스 식별자를 의존성 순서대로 모은다. 필수 서비스가 빠져 있으면 실행 자원을 바꾸기 전에 준비를 중단한다. 선택 서비스는 없어도 된다. 구성 검사와 실행이 같은 환경을 사용하며 생성하는 덮어쓰기 파일에는 변수 참조를 담는다. CLI `validate`는 전체 프로필 또는 선택 프로필의 순환을 검사한다. 웹은 IntelliJ 확인 항목을 별도로 표시하고 일시적 오류 뒤에는 상태 조회를 재시도한다.

## 3. 검증

Windows에서 Python 테스트 110개가 통과했고 선택 실행 통합 테스트 6개를 건너뛰었다. `node --test tests/test_web_app.js`의 테스트 2개도 통과했다. 설치된 Compose CLI로 Registry에만 있는 변수 해석, 직렬화된 구성에서 리터럴 값 유지, 누락 DB 거부, 데모 `dummy`와 `real` 검사 결과를 확인했다. 회귀 테스트에서는 모의 Compose 구성 검사와 실행에 같은 환경이 전달되는지 비교했다. 이번 작업에서 컨테이너를 시작하지 않았다.

## 4. 재개 지점

다중 앱 통합 검증에서 실제 macOS IntelliJ Debug 세션으로 가져온 모듈과 메인 클래스를 확인한다.
