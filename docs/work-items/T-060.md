## 1. 설계

`prepare <app-id> --project <directory> --profile <profile>`로 등록을 읽고 대상의 전체 의존성을 준비한다. 대상 선택 후 참조와 순환을 다시 검사한다. process/Compose 대상은 의존성 뒤에 실행하고 readiness를 확인한다. IntelliJ 대상은 전용 XML과 필요한 Spring YAML을 만들고 의존성 완료 후 Debug 가능 상태를 반환한다. IDE의 Debug 자동 클릭·시작은 T-120이다.

`--mode dummy`는 dummy/local-mock/mock, real은 real/local-real 중 한 프로필로만 대응될 때 사용할 수 있는 별칭이다. 여러 별칭이 존재하면 --profile을 요구한다. 프로필의 selections가 실제/대역과 각 하위 그래프를 정하며 자동 추측하지 않는다. CLI와 웹은 같은 prepare/stop 함수를 사용한다.

IntelliJ Spring 생성기(T-140)를 재사용하고 Spring 설정이 없는 일반 JVM 구성도 생성한다. Spring 설정이 없으면 기존 명시적 additional-location을 보존한다. fromEnv 실제 비밀값을 env/VM XML로 영구 저장하는 경로는 계속 거부한다. Spring YAML의 환경 placeholder 값은 IntelliJ가 상속하는 환경에서 사용자가 제공해야 한다.

## 2. 개발

- injector.py: prepare/stop/serve, 대상 positional, mode 별칭. 기존 데모 명령 유지.
- injector_core/runtime.py: 선택→전체 검증→순서 실행→Debug 준비 결과.
- rendering.py: 일반 IntelliJ 구성 생성 허용. 기존 render 명령의 Spring 요구 조건 유지.
- examples/demo/registry.json, docker/prepare-compose.yaml: 실행 가능한 dummy/real 예시. 전용 Compose 프로젝트명, 호스트 19081/19082/19379, 메인 19080.
- 데모의 catalog→redis와 main→redis는 다단계·공유 의존성 시연이다. Catalog의 실제 Redis 접근을 의미하지 않는다.
- 데모 Main.java: 생성 endpoint URL의 trailing slash를 처리해 /product 호출의 중복 슬래시 방지.

지원 제한은 README에 명시했다. 하위 IntelliJ 앱 자동 실행, Spring process/Compose 경로, Compose VM 합성은 후속 범위다. UI 설정 편집도 이번 범위가 아니다.

## 3. 검증

- `python injector.py prepare platform-service --project examples/demo --mode dummy`와 real 모두 성공했다.
- 실제 생성 XML의 VM 인자·env로 Java Main을 실행하고 /demo 200에서 profile=real, message=prepared from the local UI, downstream source=real을 확인했다. 이 검증은 IDE Debug 검증과 구분한다.
- 실제 process 대상과 두 단계 의존성의 readiness·env 응답은 자동 테스트로 검증했다.
- 기본 전체 90개 중 84개 통과, 기존 통합 6개 skip. 이전 Spring/Vault 통합 결과는 T-140에 있으며 이번 실행 결과로 재인용하지 않는다.
- 새 Injector-dummy/real-platform-service 구성의 IntelliJ 브레이크포인트는 이번에 검증하지 못했다. 기존 T-000의 IDE 검증을 이 구성의 검증으로 대체하지 않는다.
- 2026-11-18 Windows JDK 25 검증에서 생성된 dummy XML의 메인 클래스·VM 옵션·env로 JVM을 띄우고, JDK 디버거로 `poc.Main:31` 브레이크포인트를 확인했다. 임시 hosts의 커스텀 이름으로 WireMock에 연결했고 `/demo`에서 dummy 프로필과 WireMock 응답을 받았다. IntelliJ 화면에서 실행 구성을 선택하는 경로는 아직 검증이 남았다.

## 4. 재개 지점

코드 흐름 구현 완료. 새 구성은 IntelliJ에서 Maven 프로젝트를 열고 Main.java의 응답 생성 줄에 breakpoint를 둔 뒤 Debug·/demo 호출로 추가 검증한다. T-150 화면 실제 클릭도 별도 미검증이다. 후속 T-070에서 hosts/DNS를 다룬다.
