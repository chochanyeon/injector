# T-060. 대상 앱 실행 파이프라인

[작업 인덱스](../index.md) · 선행 작업: T-030, T-050

| 설계 | 개발 | 검증 |
|---|---|---|
| 초안 | 미착수 | 미수행 |

## 1. 설계

- 관련: R-01~R-04, R-09~R-10, D-01.
- 산출물: 대상 선택 → 계획 검증 → 의존성 준비 → 설정 적용 → 대상 앱 실행을 연결한 흐름.
- 완료 기준: CLI·Docker 대상은 의존성 준비 후 시작한다. IntelliJ 대상은 전용 실행 구성을 준비하고 Debug 진입 시점을 명확히 한다. IDE 직접 자동 시작은 T-120과 구분한다.

상세 설계·선택지·결정 이유는 이 절에 이어서 기록한다. 공통 요구사항은 [전체 설계](../design.md)를 참조한다. 현재는 작업 범위를 정한 초안이며 구현 설계가 완료된 상태는 아니다.

## 2. 개발

상태: 미착수. 이 작업의 구현 변경은 아직 없다.

재사용할 선행 결과: T-140의 render_node가 Spring override YAML과 IntelliJ 실행 구성을 생성한다. 의존성 준비·대상 실행 파이프라인에 연결한 상태는 아니므로 T-060에서 이 생성기를 재사용해 연결한다.

설계에서 정한 산출물을 구현한 뒤 변경 파일·핵심 동작·남은 내용을 여기에 기록한다. 스키마·문서가 산출물인 작업은 그 파일과 작성 결과를 개발 산출물로 기록한다. 설계 절 작성만으로 개발 완료로 표시하지 않는다.

## 3. 검증

상태: 미수행. 아래는 수행할 검증이며 통과한 결과가 아니다.

- 검증: 대상 앱의 두 단계 이상 하위 의존성까지 순서대로 준비하고, 마지막 앱에 계산한 설정이 전달되는지 확인한다. IntelliJ 브레이크포인트도 별도로 확인한다.

검증 후 실제 명령·환경·관찰 결과·통과 여부·미검증 범위를 이 절에 남긴다. 실패하면 재현 방법과 남은 문제를 기록한다.

## 4. 재개 지점

- 다음 조치: 위 산출물과 완료 기준을 바탕으로 필요한 구체 설계를 확정하고 근거를 기록한다.
- 진행 중 변경: 없음.
- 완료 처리: 위 완료 기준과 검증 근거를 확인한 뒤 인덱스의 설계·개발·검증 상태를 함께 갱신한다.
