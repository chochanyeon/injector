## 1. Design

Use `prepare <app-id> --project <directory> --profile <profile>` to select the target, validate references and cycles, and prepare its dependencies. Process and Compose targets start and wait for readiness. IntelliJ targets receive XML and any Spring YAML and can be debugged once dependencies are ready. T-120 covers automatic IDE launch.

`--mode dummy` matches exactly one of dummy/local-mock/mock. `--mode real` matches exactly one of real/local-real. Use an explicit profile if aliases are ambiguous. Selections determine the graph. CLI and UI share prepare and stop.

Reuse T-140 rendering for plain JVM and Spring. Preserve an explicit additional location when no Spring YAML is generated. Keep environment and VM secret values out of XML. Supply Spring placeholders in the environment inherited by IntelliJ.

## 2. Development

Added commands and aliases in `injector.py`, the runtime pipeline, plain IntelliJ rendering, and demo registry/Compose. Demo ports include 19081, 19082, 19379, and main 19080. Catalog and main share Redis to demonstrate dependency order. The Catalog app does not read Redis. Main handles trailing slashes before calling `/product`. The README lists runner limits and follow-on scope.

## 3. Verification

Dummy and real prepare both passed. Java Main launched with generated XML arguments and environment and returned `/demo` HTTP 200, the real profile, the configured message, and real downstream. Automated tests exercised process targets, readiness, two dependency levels, and environment injection. The default suite passed 84 of 90 tests with six integrations skipped.

On November 18, 2026, Windows JDK 25 ran the dummy configuration. A JDK debugger paused at `poc.Main:31` and the app reached WireMock through a custom hostname in a temporary hosts file. IntelliJ selection and breakpoint verification for the new configurations remain pending.
