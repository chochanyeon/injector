## 1. 설계

관련: R-01, R-08, D-03. 프로젝트별 등록을 읽는 검증 경로를 기존 단일 데모 명령과 함께 제공한다. 이 단계에서는 서비스 실행과 설정 합성을 하지 않는다.

### 1.1. CLI와 입력

`python injector.py validate --project <프로젝트 디렉터리> [--profile <이름>]`으로 그 디렉터리의 UTF-8 `registry.json`을 읽는다. 상대 경로는 명령 실행 위치 기준이고, 등록 내부의 프로젝트 경로는 선택한 프로젝트 루트 기준이다. 등록 파일 이름은 v1에서 `registry.json`으로 고정했다.

프로필을 지정하면 그 프로필의 선택·주입 참조를 검사하고, 생략하면 모든 프로필을 검사한다. 자료형·전역 노드·모든 variant의 의존 ID·준비 기준은 프로필 선택과 관계없이 검사한다. 선택된 그래프에 필요한 variant 선택은 명시되어 있어야 한다.

기존 plan/generate/up/down/run 명령은 mock/real 데모 동작을 유지한다. `--project`를 이 명령에 넘기면 현재 미지원이라고 알린다. `validate`에서 `--infra`와 `--main-docker` 기동 옵션을 사용하지 않는다.

### 1.2. 검사 범위

- JSON 파싱: 중복 속성, NaN 등 비표준 상수, 잘못된 UTF-8·JSON을 거부한다.
- T-010 JSON Schema: 필수값·속성·버전·포트·실행 타입.
- 의미 검사: 중복 노드 ID, 존재하지 않는 의존 ID, 알 수 없는 선택 노드·variant·override, 앱이 아닌 실행 대상, 선택 누락.
- 주입: 대상이 직접 선언한 의존성인지, 선택된 variant에 접속점·호출자 context가 있는지, 환경변수 키 형태가 유효한지.
- 준비 기준: 자기 접속점 존재, HTTP 프로토콜 일치, Compose readiness와 실행 타입 일치.
- 프로젝트 경로: workingDirectory/projectPath/Compose file의 절대 경로·다른 드라이브·UNC·프로젝트 루트 이탈을 거부한다. 심볼릭 링크를 따라 해석한 결과도 루트 내부여야 한다.

앱·Compose 파일의 실제 존재, 포트 가용성, DNS, 자격증명 존재는 기동 전 후속 단계의 책임이다. 검증 시 파일 실행이나 환경변수의 비밀값 조회를 하지 않는다. 순환 그래프는 표현·로딩할 수 있으며 DFS 단계인 T-040에서 실행 불가로 판정한다.

### 1.3. 오류와 결과

검증 실패는 종료 코드 1, 사용법 오류는 2다. 성공 시 버전·노드 수·검사한 프로필 이름만 출력한다. 오류에는 위치·검사 종류·문제가 있는 식별자를 제공하고 원본 설정값은 출력하지 않는다. JSON Schema 오류의 원문에는 실제 값이 포함될 수 있으므로 그대로 로그에 넣지 않는다.

## 2. 개발

- [registry.py](../../injector_core/registry.py): 순수 로더, 구조·참조·경로 검사, `RegistryError`.
- [injector.py](../../injector.py): validate 명령·--project·프로필 선택. 기존 데모 분기는 유지.
- [test_registry.py](../../tests/test_registry.py): 외부 프로젝트·상대/공백 경로, 참조·오류·무기동 검증.
- README와 등록 예시에 현재 명령 및 미지원 실행 범위를 기록했다.

실행용 레지스트리는 Python dict로 반환한다. 아직 정규화 모델·주소 계산·실행 어댑터를 추가하지 않았다. 원본 값을 유지해 T-030에서 합성과 출처 추적을 구현할 수 있다.

## 3. 검증

2026-11-17에 `python -m unittest discover -s tests -v`를 실행해 총 25개(기존 POC 2개, 스키마 8개, 로더·CLI 15개) 통과를 확인했다.

핵심 결과:

- 임시 외부 프로젝트와 다른 구조의 프로젝트를 읽었고, 공백 경로와 상대 경로를 확인했다.
- Windows C: 임시 디렉터리와 I: 작업공간 사이의 상대 경로를 만들던 테스트 오류를 수정했다. 상대 경로 검증은 동일 드라이브의 실제 작업 디렉터리에서 수행한다.
- 중복 ID, 누락 참조, 잘못된 모드·접속점, 루트 이탈, JSON 오류를 재현했다.
- 검증 명령이 subprocess나 XML 생성을 호출하지 않고 디렉터리에 추가 파일을 만들지 않음을 검사했다.
- 비밀값이 포함된 잘못된 입력에 대해 오류·CLI stderr에 그 값이나 traceback이 출력되지 않음을 확인했다.
- `python injector.py validate --project examples/registry --profile local-real` 성공.
- `python injector.py plan --profile real`로 기존 데모 명령의 출력을 확인했다.

앱 기동·Docker·IntelliJ 통합 검증은 이번 작업에서 수행하지 않았다. 런타임 실행 기능이 완료되었다는 결과가 아니다.
