# T-050. 실행·준비 상태 확인

[작업 인덱스](../index.md) · 선행 작업: T-040

| 설계 | 개발 | 검증 |
|---|---|---|
| 초안 | 미착수 | 미수행 |

## 1. 설계

- 관련: R-03, R-04, R-09, D-05~D-06.
- 산출물: 계획에 따라 로컬 프로세스·Compose 자원을 준비하고 상태를 확인하는 실행 경로.
- 완료 기준: 하위 의존성 준비를 기다린 뒤 다음 노드를 실행한다. 프로세스 시작과 사용 준비를 구분하며, 시간 초과·종료를 감지한다. 생성 자원과 기존 자원의 소유권을 기록한다.

상세 설계·선택지·결정 이유는 이 절에 이어서 기록한다. 공통 요구사항은 [전체 설계](../design.md)를 참조한다. 현재는 작업 범위를 정한 초안이며 구현 설계가 완료된 상태는 아니다.

## 2. 개발

상태: 미착수. 이 작업의 구현 변경은 아직 없다.

설계에서 정한 산출물을 구현한 뒤 변경 파일·핵심 동작·남은 내용을 여기에 기록한다. 스키마·문서가 산출물인 작업은 그 파일과 작성 결과를 개발 산출물로 기록한다. 설계 절 작성만으로 개발 완료로 표시하지 않는다.

## 3. 검증

상태: 미수행. 아래는 수행할 검증이며 통과한 결과가 아니다.

- 검증: 지연 준비, 시작 실패, 준비 시간 초과, 기존 포트 점유를 재현한다. 실패 시 그 자원에 의존하는 앱이 시작되지 않아야 한다.

검증 후 실제 명령·환경·관찰 결과·통과 여부·미검증 범위를 이 절에 남긴다. 실패하면 재현 방법과 남은 문제를 기록한다.

## 4. 재개 지점

- 다음 조치: 위 산출물과 완료 기준을 바탕으로 필요한 구체 설계를 확정하고 근거를 기록한다.
- 진행 중 변경: 없음.
- 완료 처리: 위 완료 기준과 검증 근거를 확인한 뒤 인덱스의 설계·개발·검증 상태를 함께 갱신한다.
