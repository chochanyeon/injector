## 1. 설계

계산된 DFS 후위 순서대로 process·Compose·external 노드를 준비한다. 하위 노드 readiness가 성공한 뒤 상위 노드를 시작한다. 모든 노드의 설정·실행 파일·Compose 서비스·readiness 계약을 먼저 검사한다. process는 argv 실행이며 shell을 쓰지 않는다. VM 인자는 java 실행 파일에만 붙인다. HTTP 2xx·TCP 접속·Compose healthcheck를 구분한다. 프로세스/컨테이너 조기 종료와 시간 초과는 실패다.

포트가 열려 있다고 기존 서비스를 같은 의존성으로 간주하지 않는다. 기존 Compose 프로젝트/서비스와 충돌하면 거부한다. Docker에는 --no-deps를 전달하여 registry 밖의 depends_on을 자동 기동하지 않는다. 완료 기준은 실제 순서·지연 대기·실패 전파·소유 자원 정리·기존 자원 보호다.

세션 JSON은 PID+생성 시각 또는 고유 컨테이너 라벨만 저장한다. argv·해석된 설정값은 저장하지 않는다. 종료는 프로세스 생성 시각과 컨테이너 세션 라벨을 확인한다. OS 파일 잠금으로 같은 프로젝트의 prepare/stop 동시 실행을 거부한다. 재준비는 이전 소유 세션을 종료하고 새로 준비하며 실패 시 새 세션을 역순 정리한다. 다중 세션 공유·재사용·볼륨 삭제 정책은 T-090에 남긴다. 네트워크·볼륨과 IDE에서 사용자가 시작한 앱은 제거하지 않는다.

Compose 환경 override에는 실제 값 대신 임시 child 환경변수의 interpolation 참조만 기록한다. env 실제 값은 Docker 자식 환경으로 전달한다. Compose VM 합성, Spring YAML 컨테이너 마운트·process 전달은 현재 거부한다. process 로그와 Docker 명령 출력은 진단 응답으로 노출하지 않는다.

참고: [Docker Compose up](https://github.com/docker/compose/blob/main/docs/reference/compose_up.md), [psutil 프로세스 식별·종료 API](https://psutil.readthedocs.io/stable/index.html).

## 2. 개발

- injector_core/runtime.py: 사전 검사, runner, readiness, 잠금, 세션 저장·stop·rollback.
- requirements.txt: psutil 7.2.2 추가. Windows에서도 PID 재사용을 구분하고 자식 프로세스를 종료한다.
- tests/test_runtime.py: 다단계·공유 의존성, env 주입, 조기 종료, 지연, timeout, busy port, 전체 사전 검사, 재준비, PID 식별 보호.

남은 범위: 여러 실행 세션의 의존성 공유, crash 순간의 시작/기록 사이 복구, 로그 수집, 실행 중 이후의 지속 모니터링, Compose 네트워크 수거. 일반적인 신뢰하지 않는 레포의 명령 실행 sandbox는 제공하지 않는다.

## 3. 검증

2026-11-17 Windows/Python 3.14, Docker Compose v5.1.1에서 수행했다.

- 기본 전체 suite 90개 중 84개 통과, 기존 외부 연동 6개 skip. process fixture가 실제 로컬 HTTP 서버를 띄워 순서·값·정리까지 확인한다.
- 실제 demo dummy/real prepare 모두 redis→catalog→platform-service 순서로 완료했다. Redis/WireMock/Java Catalog 컨테이너가 healthy가 된 뒤 다음 단계가 시작됐다.
- 프로필 전환 시 이전 세션 컨테이너를 종료하고 새 라벨 세션으로 실행했다. 기존 injector-poc 자원은 건드리지 않는다.
- 실패 시험에서 상위 노드 시작 없음, timeout/조기 종료 시 세션 제거, foreign listener 생존, PID 생성 시각 불일치 시 종료 거부를 확인했다.

## 4. 재개 지점

첫 실행 범위 완료. T-090에서 다중 세션·장애 복구와 자원 보존 정책을 확대한다. 현재 지원되지 않는 주입 채널을 registry 필드 추가로 우회하지 않는다.
