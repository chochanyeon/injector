## 1. Design

The user prioritized a local Vault-style mock ahead of T-050. This records the original single path. [T-131](T-131.md) added service IDs and removed the injector-demo path.

The historical contract was `GET /v1/secret/data/injector-demo` with a fixed local `X-Vault-Token`. KV v2 responses use `data.data` and `data.metadata`. Prioritized mappings return 200 for a match, 403 for a missing or wrong token, and JSON 404 for other authenticated `/v1/` paths, methods, or queries. The fixed token selects fixtures. Login, token lookup and renewal, leases, KV v1, versioned reads, writes, namespaces, TLS, and company SDK discovery remain outside scope. [Vault KV v2 read](https://developer.hashicorp.com/vault/api-docs/secret/kv/kv-v2)

Use a separate `vault-mock` service, with `localhost:18083` on the host and `vault-mock:8080` in Docker. Legacy up, generate, run, and plan enable it through `--with-vault`. The original demo settings define its host and container URLs, path, and local token. The Python consumer parses the message and feature flag without displaying credentials. Java Main receives configuration and leaves the API check to the Python consumer. The mock fits a general Compose node later.

## 3. Verification

On November 17, 2026, Docker 29.4.0 with the Linux engine passed WireMock healthchecks, Compose config, and internal `vault-mock:8080` lookup. With `INJECTOR_TEST_VAULT_URL=http://127.0.0.1:18083`, 58 tests passed, including four integrations. Verified fixture values, 403 and 404 responses, feature flag and parsing, hidden credentials, and opt-in configuration. `vault-demo` reported a message and `databaseConfigured=true`. The default suite ran 54 and skipped four integrations. Company SDKs, Java compilation, and IntelliJ Debug were outside this check.
