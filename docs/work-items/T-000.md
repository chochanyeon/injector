## 1. Design

Verify JVM injection and direct debugging in IntelliJ while switching the dependency API between WireMock and real Catalog. Merge shared and profile settings and generate IntelliJ XML and Docker configuration. PostgreSQL, Kafka, and Redis are optional. The developer starts Debug manually. Application discovery, DFS execution, and arbitrary projects were outside this initial POC. [Design, section 14](../design.md#14-poc-configuration-and-intellij-integration)

## 2. Development

[injector.py](../../injector.py) merges settings, generates XML, calls Compose, and runs Java. [Configuration tests](../../tests/test_injector.py) cover profiles and output. The [demo](../../examples/demo/) contains Java, Maven, Docker, and WireMock mappings. Profile environment values override shared values, and JVM option arrays are concatenated. Address translation is demo-specific. Generated XML, Docker settings, builds, and IDE metadata stay in the demo folder and out of Git.

Implementation commits: `faea324`, `8522272`, and `5fce26b`. [Project status](../status.md)

## 3. Verification

On November 16, 2026, two configuration tests passed. Local JVM and Docker verified mock and real API calls and injection. IntelliJ IDEA 2025.3.3 with JDK 21 verified Debug and breakpoint pause and resume. PostgreSQL query, Redis PING, and Kafka topic creation were checked separately.

The IntelliJ check predates the demo move. After the move, XML paths, module names, and local JVM and Docker calls were rechecked. Direct demo use of PostgreSQL, Kafka, and Redis remains unverified. [Verification procedures](../validation-history.md)
