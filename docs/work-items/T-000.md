## 1. 설계

목표는 IntelliJ에서 메인 JVM을 직접 디버깅하면서 설정을 주입하고, 의존 API를 WireMock·실제 Catalog 사이에서 전환할 수 있는지 확인하는 것이다. 공통·프로필별 설정을 합성해 IntelliJ 실행 구성 XML과 Docker용 설정을 생성한다. DB·Kafka·Redis는 선택적으로 기동한다.

별도 IDE 플러그인은 사용하지 않는다. 메인 앱의 IntelliJ Debug는 개발자가 직접 시작한다. 앱 등록·DFS 실행·임의 프로젝트 지원은 이 POC의 완료 범위에 포함하지 않는다. 상세한 선택은 [전체 설계 14절](../design.md#14-현재-poc의-설정-관리-및-intellij-연동)을 참조한다.

## 2. 개발

- [injector.py](../../injector.py): 공통·프로필 설정 합성, XML 생성, Compose 호출, CLI Java 실행.
- [설정 테스트](../../tests/test_injector.py): 프로필 전환·생성 결과 검사 2개.
- [데모 프로젝트](../../examples/demo/): Java 앱, Maven, 설정, Docker, WireMock 매핑.
- 공통 env에 프로필 env를 덮어쓰고 VM 옵션은 배열을 연결한다. 주소는 데모에 맞춰 변환하며 범용 해석기는 아직 없다.
- 생성 XML·Docker 설정·빌드 결과·IDE 설정은 데모 폴더에 보관하고 Git에서 제외한다.

구현 근거: `faea324`, `8522272`, `5fce26b`. 현재 구현의 전체 제한은 [현황](../status.md)에 있다.

## 3. 검증

2026-11-16에 다음을 확인했다.

- `python -m unittest discover -s tests -v`: 2개 통과.
- 로컬 JVM·Docker에서 mock/real의 설정 주입과 API 응답 확인.
- IntelliJ IDEA 2025.3.3 / JDK 21에서 Debug와 브레이크포인트 중단·재개 확인.
- PostgreSQL 쿼리, Redis PING, Kafka 토픽 생성 확인.

IntelliJ 조작은 데모 디렉터리 분리 전에 검증했다. 분리 후에는 XML 경로·모듈과 로컬 JVM·Docker 호출을 확인했다. 데모가 DB·Kafka·Redis를 실제로 사용하는 통합 시나리오는 검증하지 않았다. 환경·재현 절차는 [기존 검증 이력](../validation-history.md)에 있다.
