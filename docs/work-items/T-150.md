## 1. 설계

정적 HTML만으로 로컬 Docker·프로세스를 제어할 수 없어 Python 표준 라이브러리 웹 서버와 HTML/CSS/JS를 묶는다. 외부 배포 없이 127.0.0.1:18770에 바인딩한다. Windows 더블클릭 실행 파일은 pythonw로 서버와 브라우저를 연다. Python 의존성 설치는 최초 한 번 필요하다.

프로젝트 경로 불러오기→프로필·앱 선택→DFS 계획 확인→실행 환경 준비→노드별 상태→IntelliJ Debug 안내가 핵심 흐름이다. 종료 버튼도 제공한다. 편집기·비밀값 입력 UI는 만들지 않는다. 브라우저를 닫아도 서버/의존성은 유지한다. 준비/종료는 한 번에 하나만 실행하며 별도 worker로 HTTP 응답을 유지한다.

Host를 로컬 주소로 제한하고 변경 API에 세션 토큰과 동일 Origin을 요구한다. CORS를 열지 않고 정적 파일은 whitelist로만 제공한다. 결과와 진행 기록에는 설정값을 포함하지 않는다. 같은 사용자의 로컬 명령 제어 도구이며 다중 사용자 인증 서비스가 아니다.

완료 기준: CLI와 동일 함수 사용, 계획 표시, 준비/종료 API 실제 실행, 동시 실행 거부, 외부 Host/Origin 거부, 사용자에게 실패 표시. 별도로 브라우저 실제 클릭·레이아웃 확인이 필요하다.

## 2. 개발

- injector_core/web.py: HTTP API, 비동기 job, loopback/Host/Origin/token 검사, 동일 서버 재열기.
- injector_core/web/index.html, app.js, style.css: 한글 로컬 준비 화면. 프로젝트/프로필/앱/계획/단계/Debug 안내.
- Start-Injector.vbs: venv pythonw 우선, 숨김 실행, 시작 실패 안내. README 사용법 포함.
- tests/test_web.py: 정적 파일·등록 조회·worker·진행 결과·보안 검사·예상 밖 예외 값 비노출.
- 상단 홍보 문구와 장식용 단계 라벨을 제거했다. 프로젝트 선택과 준비 현황이 바로 표시된다.

## 3. 검증

- node --check injector_core/web/app.js 통과.
- 웹 테스트 5개 통과. 전체 suite 결과는 T-050과 같다.
- 문구 정리 후 실제 서버의 HTML과 CSS에서 제거된 문구와 유지된 실행 버튼·상태 영역을 확인했다. 웹 테스트 5개를 다시 통과했다.
- 실제 로컬 서버에 POST /api/prepare를 전달해 dummy 준비 202→succeeded 및 실제 Redis/WireMock healthy·전용 XML 경로를 확인했다. real 세션의 이전 자원 정리도 관찰했다.
- 브라우저 제어 연결이 unavailable이었고, native Chrome 접근 승인도 timeout으로 종료되어 실제 브라우저 클릭과 시각 레이아웃은 확인하지 못했다. API 성공을 클릭 검증으로 표시하지 않는다.
- 2026-11-18 Windows에서 VBS를 CScript로 호출해 기존 서버를 다시 여는 경로의 종료 코드 0을 확인했다. 기존 서버를 종료하고 WScript로 VBS를 호출했을 때 새 리스너와 HTTP 200도 확인했다. 브라우저 연결 장애가 지속돼 화면의 준비·종료 버튼과 레이아웃은 직접 확인하지 못했다.

## 4. 재개 지점

브라우저에서 실제 준비/종료 버튼을 누르고 800px 이하 화면과 긴 프로젝트 경로 표시를 확인한다.
