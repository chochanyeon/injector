# T-120. Automatic preparation before IDE execution

## 1. Design

Use IntelliJ IDEA's built-in local External Tool as a Before Launch task for an Application configuration. A user installs the task once for the selected launch. It prepares dependencies synchronously and reports failure via the exit code. The imported app settings must match the generated revision. [Design](../design.md) · [IntelliJ External Tools](https://www.jetbrains.com/help/idea/configuring-third-party-tools.html)

## 2. Development

`ide-tool` generates XML and optional Spring YAML and prints IDE tool fields without starting dependencies. Its command checks the expected configuration before changing the current session and preserves the imported configuration on repeat launches. A matching and healthy managed session can be reused. Explicit host environment references used by managed nodes disable reuse. Compose runs under the selected source directory for both preflight and startup.

## 3. Verification

Windows subprocess tests verified the generated command, healthy-session reuse, nonzero exit on changed app settings, and cleanup after a simulated interrupt. The installed IntelliJ IDEA 2025.3.3 task implementation accepts exit code zero and rejects other codes. Direct Mac and Windows IDE Run/Debug interaction still needs a desktop walkthrough.

A real Compose check verified that a nested Compose file reads `.env` from the selected source root.

## 4. Resume point

Attach the tool to an imported work-project configuration and verify Run, Debug, and cancellation in the IDE on macOS. Use `stop` to recover from a forced termination.
