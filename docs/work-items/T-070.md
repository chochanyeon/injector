## 1. Design

Use registry `nameMappings`. The `hosts` method maps a hostname to a loopback IP. The `external` method declares an existing resolver and expected IP. Preview, apply, and remove are separate. Entries are owned by the project path, matching manual entries are preserved, and conflicting addresses or owners block changes. Removal can use the original path after moving a project.

Apply and remove require an elevated terminal. Prepare and the browser read resolution. Compose uses service names or `extra_hosts`. Prepare checks only selected host endpoints before changing an existing session or generated files.

## 2. Development

Implemented validation, planning, preserve and restore behavior, Windows file replacement and locking in `hostnames.py`. Windows preserves DACL through ReplaceFileW and checks for updates before replacement. Registry and runtime validate relevant mappings, and the CLI exposes hosts operations. [ReplaceFileW](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)

## 3. Verification

Windows system-hosts preview showed two proposed lines. Temporary hosts tests covered apply, reapply, remove, BOM, newlines, manual entries, conflicts, invalid names/IPs, and keeping the prior session after a resolution failure. A JVM used temporary hosts to call WireMock through `catalog.injector.test`, after which the file was restored byte for byte. Elevated system apply remains pending.
