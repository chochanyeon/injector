# T-310. Compare one HTTP scenario across worktrees

**English** · [한국어](T-310.ko.md)

[Work index](../index.md) · Prerequisites T-260 and T-300

## Design

Run one scenario against two existing checkouts in sequence with the same target and profile. Allow a shared central registry. Reuse the recorder, artifact contract, and Verifier so both sides can be compared in the browser afterwards. Check both plans and active sessions before starting, then preserve the recorder's ownership checks during each run.

Acceptance requires a comparison between real Git worktrees, cleanup after both runs, and rejection of active sessions and existing output directories.

## Development

The `compare-worktrees` CLI reads the scenario once, validates both selected edges, and checks that neither checkout has an active Injector session. It creates a fresh output directory, uses the existing recorder on each checkout, and prints the usual Verifier report with artifact paths.

## Verification

- Six HTTP observation tests passed on Windows. They covered equivalent results, changes to downstream request fields, cleanup with reused ports, and rejected attempts to use an active session or existing output directory.
- In a temporary Git repository with two actual worktrees and a shared registry, the candidate changed only the downstream warehouse. Both target responses stayed the same, Verifier reported the changed field, and both sessions stopped.
- The default Python suite passed 135 tests with seven opt-in tests skipped.
