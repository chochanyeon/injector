## 1. 설계

관련: R-06, R-09, 공통 설계 15절. 선택한 프로필의 targets에서 시작해 선택된 variant의 dependencies만 DFS 후위 순회한다. 공통 노드는 하나의 ID로 참조하고 한 번만 실행 순서에 넣는다.

### 1.1. 순서와 순환

프로필의 targets 순서와 각 variant의 dependencies 순서를 보존한다. 방문 전·방문 중·방문 완료 상태를 구분하고, 방문 중 노드를 다시 만나면 실제 순환 경로를 오류로 알린다. 도달하지 않는 노드는 계획에 포함하지 않으며, 그 안의 순환도 탐색하지 않는다. 전역 ID·참조 형식 검사는 여전히 T-020에서 수행한다.

명시적인 스택으로 DFS를 구현해 Python의 재귀 깊이에 의존하지 않는다. 여러 target이 공통 자원을 요구할 때 앞서 준비하도록 한 번만 포함한다. 실제 앱을 대역으로 선택하면 그 대역의 dependencies만 순회한다. 다른 앱이 같은 DB를 필요로 하면 DB는 여전히 계획에 남는다.

### 1.2. 단일 선택과 충돌 경계

프로필은 ID마다 하나의 variant만 선택한다. 중복 JSON 속성·노드 ID는 로더가 이미 거부하므로 같은 실행에서 같은 ID를 두 모드로 준비하는 모호한 상태를 만들지 않는다. 실행 설정의 자동 주입 충돌은 T-030, 실제 포트·기존 자원 충돌은 T-050 이후의 실행 단계에서 검사한다.

계획 성공은 기동 성공을 뜻하지 않는다. 명령 파일 존재, DNS, 포트 가용성, readiness, 실제 환경 참조는 기동 전 별도 검사가 필요하다.

### 1.3. 계획과 설정 해석의 분리

CLI는 `plan --project <디렉터리> --profile <이름>`이다. --project가 없으면 기존 데모 요약 동작을 유지한다. 일반 등록의 대상 목록은 프로필 targets를 사용한다.

결과는 profile, targets, order, steps다. 각 step은 node·variant·kind·runner·dependencies 메타데이터만 포함한다. 실행 명령·env·VM 옵션·비밀값을 출력하지 않는다. 프로세스·Docker·XML 생성이나 환경변수 값 조회도 하지 않는다.

실행 단계에서는 먼저 `build_plan`으로 순환을 포함한 그래프를 검사하고, order의 모든 노드에 `resolve_node`를 적용해 설정 사전 검증을 완료한 뒤 자원 기동을 시작한다. 이 연결 원칙을 테스트로 확인했으며 실제 실행 엔진 연결은 T-050에서 한다.

## 2. 개발

- [planning.py](../../injector_core/planning.py): 명시적 스택·방문 상태를 사용한 DFS 후위 계획과 순환 경로 오류.
- [injector.py](../../injector.py): --project가 있는 plan 분기. 프로필 필수·기동 옵션 금지.
- [test_planning.py](../../tests/test_planning.py): 그래프 형태·선택 모드·설정 해석 연계·무기동 CLI 검증 10개.
- README·공통 설계에 계획 기능과 실행 기능의 경계를 반영했다.

계획은 dict로 반환하며 원본 등록을 변경하지 않는다. 실행 어댑터·프로세스 수명 관리는 아직 없다.

## 3. 검증

2026-11-17에 `python -m unittest discover -s tests -v`를 실행해 총 48개 통과를 확인했다. T-040의 10개 테스트는 다음을 포함한다.

- 분기·공통 의존성: D → B → E → C → A 순서와 D의 단일 포함.
- 실제·대역 전환: real은 database → catalog → orders, mock은 catalog → database → orders. Orders도 DB를 직접 필요로 하기 때문에 mock에서도 DB가 남는다.
- 다른 DB 소비자가 없을 때 mock에서 실제 Catalog 전용 DB 제거.
- 여러 target의 공통 자원, 도달하지 않는 노드, 자기 순환·다중 노드 순환의 경로.
- 1,500개 노드 직선 그래프 처리와 누락된 선택·의존성 오류.
- 계획 후 모든 노드의 설정을 미리 해석할 수 있음.
- 환경변수를 비워도 CLI 계획이 동작하고 subprocess·XML·파일 변경이 없음.

`python injector.py plan --project examples/registry --profile local-real`과 local-mock 명령도 확인했다. Docker·IntelliJ·실제 앱 실행은 이번 검증에 포함하지 않았다.
