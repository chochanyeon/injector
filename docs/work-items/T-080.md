# T-080. 의존성별 실제 실행·모의 대체

[작업 인덱스](../index.md) · 선행 작업 T-040, T-050

| 설계 | 개발 | 검증 |
|---|---|---|
| 완료 | 완료 | 완료(기본 데모·프로세스 범위) |

## 1. 설계

프로필 selections를 기본으로 쓰고 요청마다 노드별 variant 선택을 덮어쓴다. 새 하위 의존성도 같은 프로필에서 선택해야 한다. 변경된 그래프의 참조·순환을 재검사하고 계획과 주입을 같은 선택에서 계산한다. 실제 앱에만 필요한 자원은 대역으로 바꿀 때 제외하고, 다른 경로가 필요한 공유 자원은 한 번 준비한다.

## 2. 개발

CLI는 plan과 prepare에 반복 가능한 `--variant NODE=VARIANT`를 제공한다. 웹은 노드별 선택으로 준비 순서와 그래프를 갱신한다. 선택은 요청 단위이며 현재 프로필명으로 Debug 구성을 생성한다. 기본 데모는 dummy에서 Catalog를 real로 바꿀 경우를 위해 PostgreSQL의 variant도 미리 선언했다.

## 3. 검증

- 전체 실제·전체 대역·혼합을 로컬 프로세스 fixture로 각각 실행했다. 공유 노드 유지, 실제 전용 DB 제외, 선택된 주소 주입과 준비 순서를 확인했다.
- 웹 API에서 plan과 graph가 동일한 임시 선택을 반영하고 중복 CLI 형식의 요청을 거부하는지 확인했다.
- 브라우저에서 dummy의 Catalog만 real로 선택해 PostgreSQL이 계획과 그래프에 추가되는 것을 확인했다. Windows Docker에서 해당 조합을 준비해 실제 Catalog와 Vault 대역의 응답, 생성된 IntelliJ 설정의 Catalog 주소를 확인한 뒤 세션을 종료했다.

## 4. 재개 지점

멀티모듈 도그푸딩으로 스킬 조사부터 registry 작성, 혼합 준비와 Debug까지 이어서 검증한다. 작업 인덱스의 다음 기능 구현은 T-090이다.
