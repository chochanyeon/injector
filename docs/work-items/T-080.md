## 1. Design

Use profile selections as defaults and permit per-request variant overrides. New transitive dependencies need selections in the same profile. Revalidate references and cycles and use the same selection for planning and injection. A mock can remove real-only infrastructure, while shared resources needed by other paths remain.

## 2. Development

Added repeatable `--variant NODE=VARIANT` to plan and prepare. The browser updates plan and graph for a request. The Debug configuration keeps the selected profile name. The demo predeclares PostgreSQL for the real Catalog variant.

## 3. Verification

Process fixtures covered all-real, all-mock, and mixed graphs, shared nodes, real-only DB removal, addresses, and order. API checks covered plan/graph consistency and duplicate override rejection. In the browser, switching Catalog to real in dummy added PostgreSQL to the graph and plan. Windows Docker then verified real Catalog, the Vault mock, and the generated IntelliJ address before cleanup.

## 4. Resume point

Verify an actual multimodule project from skill discovery through Debug. T-090 follows.
