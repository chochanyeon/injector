# T-320. CLI에서 레지스트리 실행 조건 검사

[English](T-320.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-220, T-300

## 설계

초기 등록과 자동화를 위해 웹의 실행 조건 검사를 CLI 명령으로 노출한다. 중앙 레지스트리 파일과 노드별 variant 변경을 포함해 같은 실행 검사를 사용한다. 성공하면 실행 순서와 필요한 IntelliJ 확인 정보를 반환하고, 실패하면 첫 실행 조건 문제를 표시한다.

검토된 레지스트리의 검사 성공, 잘못된 variant의 검사 실패, 두 경우 모두 서비스 상태와 파일 유지 여부를 완료 기준으로 삼는다.

## 개발

`injector.py check`는 웹과 같은 `check_requirements`를 호출한다. 앱, 소스 워크트리, 선택적 중앙 레지스트리, 프로필, 노드별 variant 변경을 받는다. README와 등록 가이드에 계획 확인과 실행 준비 사이의 사용법을 추가했다.

## 검증

- Windows CLI 회귀 테스트에서 IntelliJ 대상을 확인하고 잘못된 프로세스 variant로 종료 코드 1을 받았다. 두 경우 모두 세션 파일과 실행 구성은 생성되지 않았다. 임의 확장자의 외부 레지스트리를 사용했다.
- 실제 Docker Compose CLI로 기본 데모의 IntelliJ 대상과 Pricing을 WireMock으로 바꾼 쇼핑몰의 `real` 프로필을 검사했다. 설치된 영문·한국어 등록 가이드가 저장소의 갱신 파일과 일치함을 확인했다.
- 기본 Python 테스트 136개가 통과했고 별도 설정이 필요한 7개는 건너뛰었다. 실제 실행 검증은 Windows에서 진행했다.

## 재개 지점

처음 `prepare`를 하기 전에 `check`로 등록 상태를 확인한다. 보고된 원인을 해소한 뒤 실제 대상에서 기동을 확인한다.
