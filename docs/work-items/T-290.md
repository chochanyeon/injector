# T-290. Vault settings for every shop service

**English** · [한국어](T-290.ko.md)

[Work index](../index.md) · Prerequisite T-280

## Design

Give all six shop applications a Vault path and a startup dependency. Keep both pricing implementations and check that each reads its Vault settings before serving traffic. Verify the six reads in both profiles and prove that changing the mock price in Vault changes the checkout total.

## Development

Storefront uses a Vault-provided Redis counter key. Inventory and the Java Pricing process use Vault-provided database usernames. The Pricing stub fetches configuration over the Compose network before WireMock starts and renders the price from `mockUnitCents`. Each application declares a direct `vault-mock` dependency in its registry node file.

## Verification

- Registry validation, both execution plans, and `installDist` passed on Windows.
- The live `test_shop_demo.py` run found all six service paths in the Vault journal after startup in each profile. A test override changed the wiremock quote from 999 to 1,149 cents, and the order total and HTTP recording used the new value. The test also verified that Redis used the overridden Storefront counter key.
- The default Python suite passed 129 tests with seven opt-in tests skipped. Live verification used Windows and Docker Desktop.
