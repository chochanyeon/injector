# T-220. Check registry execution requirements

**English** · [한국어](T-220.ko.md)

[Work index](../index.md) · Prerequisites T-060, T-150, and T-200

## 1. Design

Add an on-demand check for the selected source worktree, registry, app, profile, and variants. Check the dependency plan and reuse the execution preparation rules for reachable nodes. Report the first blocker without returning configuration values. The check may inspect Compose configuration but must not start or stop services or write runtime files. It cannot detect requirements absent from the registry or confirm application startup.

## 2. Development

The execution screen submits the current selection to the token-protected `/api/check` endpoint. It clears the result when the selection changes. Runtime preparation and the check share settings resolution, runner validation, and in-memory IntelliJ configuration rendering. Host resolution, port ownership, and service readiness are still checked during preparation.

## 3. Verification

The HTTP regression covers a valid selection, a broken dependency variant that still allows planning, a Compose service without a healthcheck, token enforcement, and the absence of runtime artifacts. The Compose command is mocked and asserted to use only `config`. A headless DOM check covered success, error, and discarding stale results after a worktree change.

On Windows, the full suite ran 115 tests with 109 passing and six opt-in skips. The demo's `dummy` and `real` profiles also passed with the installed Docker Compose CLI. The browser interaction was exercised in a test DOM.

## 4. Resume point

Use the browser or the [T-320 CLI](T-320.md) to check a registered work project. Source-level discovery of undeclared requirements belongs to the registration workflow.
