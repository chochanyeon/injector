# T-330. HTTP·Kafka 요청 흐름 비교

[English](T-330.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-280, T-310

## 설계

쇼핑몰의 로컬 Loki에서 요청 ID 하나의 HTTP 호출과 Kafka 이벤트를 수집한다. 두 워크트리의 선택된 응답 필드와 정규화된 이벤트를 비교한다. 시나리오가 요구한 이벤트가 확인돼야 판정한다.

동일 흐름, 앱 응답이 같은 하위 동작 변경, Kafka 소비 이벤트 누락을 각각 검증한다.

## 개발

- 버전 2 시나리오는 Loki 엔드포인트, 앱 라벨, 제한 시간, 필수 이벤트를 지정한다. 기존 관측 명령이 고유 요청 ID를 보내고, 세션 종료 전에 응답의 선택 필드와 관련 이벤트를 기록한다.
- 쇼핑몰이 아웃바운드 HTTP 호출자·대상·메서드·경로·상태를 기록한다. Kafka 발행·소비 로그는 토픽을 포함한다. Verifier는 로그 도착 순서와 무관하게 이벤트 수와 값을 비교하고, 필수 이벤트가 누락되면 판정을 보류한다.
- CLI와 웹 비교에서 두 기록 형식을 모두 처리한다. 요청 흐름 기록은 지정된 HTTP·Kafka 메타데이터를 보관하고 요청 ID와 시각은 제외한다.

## 검증

- Windows CLI에서 실제 Git 워크트리 두 곳에서 각각 이벤트 열 개를 기록해 `PASS`를 받았다. 양쪽 세션이 종료됐다.
- Windows에서 Docker로 실행한 `mock` 프로필에서 주문 응답이 그대로인 Kafka 토픽 변경을 검출했다. Kafka 소비가 관측되지 않은 경우 `INCONCLUSIVE`를 반환했다. 기존 쇼핑몰 `real`·`mock` 통합 테스트와 버전 1 가격 조회 기록도 통과했다.
- 기본 Python 테스트 137개가 통과했고 별도 실행이 필요한 8개는 건너뛰었다. Node 웹 로직 테스트 여섯 개와 실제 로컬 웹 API의 버전 2 파일 비교를 확인했다.
