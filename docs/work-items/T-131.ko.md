## 1. 설계

관련: R-13. 서비스별로 동일한 키에 다른 값이 필요하므로, 대역의 포트·주소는 공유하고 secret 경로에 서비스 ID를 넣는다. 서비스마다 별도 Vault/WireMock 인스턴스를 띄우지 않는다.

기본 요청은 `GET /v1/<mount>/data/<서비스 ID>`다. 예시는 orders와 payments를 제공한다. 두 응답의 키는 같고 message·database_username·database_password는 다르다. 알 수 없는 서비스는 다른 서비스나 공통 응답으로 대체하지 않고 JSON 404를 반환한다.

데모 설정의 vaultMock에 mount와 defaultService를 둔다. 기본값은 secret·orders다. CLI --vault-service는 대역 사용을 활성화하고 서비스 선택을 전달한다. resolve/generate에서 VAULT_PATH를 만들어 호스트·컨테이너 환경에 동일하게 넣고 VAULT_ADDR만 실행 위치에 맞춰 바꾼다.

서비스 ID는 소문자로 시작하고 소문자·숫자·하이픈만 허용한다. 슬래시·query·줄바꿈·대문자·빈 문자열을 거부한다. 서비스 등록 목록을 별도로 중복 관리하지 않으며, 매핑 파일이 없으면 실제 요청에서 404다. 일반 레지스트리와의 연결은 이후 작업에 남긴다.

KV v2 envelope·고정 로컬 토큰·미지원 API 범위는 T-130을 따른다. 경로 분리는 데이터 식별 규칙이며 서비스별 접근 권한 정책은 아니다. 업무 앱의 경로 설정 가능 여부와 SDK 호환성은 여전히 미검증이다.

## 2. 개발

- [orders.json](../../examples/demo/docker/vault-mock/__files/orders.json), [payments.json](../../examples/demo/docker/vault-mock/__files/payments.json): 서비스별 로컬 값.
- [Orders 매핑](../../examples/demo/docker/vault-mock/mappings/read-orders.json), [Payments 매핑](../../examples/demo/docker/vault-mock/mappings/read-payments.json): 정확한 경로에서 해당 파일만 반환.
- [원본 설정](../../examples/demo/config/project.json): vaultMock.mount와 defaultService.
- [Injector CLI](../../injector.py): --vault-service, 경로 생성·이름 검증, XML/Docker 환경과 소비 앱에 전달.
- [단위 검사](../../tests/test_injector.py)와 [WireMock 통합 검사](../../tests/test_vault_mock_integration.py): 경로 선택·동일 키의 값 분리·각 소비 앱 결과·미등록 경로 검사.
- 사용자 가이드와 LLM 등록 프로토콜에 서비스별 경로·응답 조사 원칙을 반영했다.

단일 injector-demo 경로와 응답 파일은 제거했다. 기존 --with-vault와 vault-demo는 기본 orders 경로를 사용한다. 소비 앱 코드는 VAULT_PATH를 읽으므로 변경하지 않았다.

## 3. 검증

2026-11-17에 대역을 재기동하고 healthcheck를 기다린 후 INJECTOR_TEST_VAULT_URL을 지정해 전체 테스트 60개를 실행했고 모두 통과했다. 5개는 실제 WireMock 통합 검사이며 기본 실행에서는 이 5개를 skip한다.

- Orders·Payments의 키 집합이 같고 database_password·message 값은 다름을 확인했다.
- 두 경로의 전체 KV v2 data가 각각의 파일과 일치했다.
- --vault-service payments로 생성한 XML과 Docker 환경 모두 VAULT_PATH가 secret/data/payments였다.
- 기본 서비스 선택, 잘못된 서비스 이름, 미등록 서비스·제거된 구 경로 404, 토큰 오류 403을 확인했다.
- `python injector.py vault-demo --vault-service orders`는 Orders local configuration, payments는 Payments local configuration을 출력했다. 비밀번호는 출력하지 않았다.

앱이 실제 DB에 접속하는 것, 회사 앱/SDK, IntelliJ 디버깅은 검증하지 않았다. 이번 변경은 대역 응답과 데모 설정 선택 범위다.
