# T-440 · 주입 규칙 검증과 수정

**[English](T-440.md)** · 한국어 · [작업 인덱스](../index.ko.md)

## 설계

저장 전에 각 프로필에서 실행할 노드의 주입 충돌을 찾는다. 환경 변수 값을 읽지 않고 프로필, 노드, 채널 및 키를 표시한다. 노드 초안에서 기존 규칙을 확인·수정·삭제하고 기존 검증 및 동시 저장 검사를 거친다.

## 개발

- Registry 검증과 런타임이 설정 우선순위와 주입 키 충돌 검사를 공유한다. 수동 설정과 충돌하면 적용되는 설정 위치를, 규칙이 중복되면 앞선 규칙 번호를 표시한다.
- 노드 편집기가 기존 규칙의 출처와 채널을 표시하고 수정 시 규칙 순서를 유지한다. 엔드포인트 후보에는 실행 대상에서 해당 노드에 도달하는 프로필을 반영한다. 초안의 실행 계획이 불완전하면 해당 프로필의 선택을 보수적으로 반영해 편집을 계속할 수 있다.

## 검증

데모에서 공통 환경 설정에 `VAULT_ADDR`를 추가해 검증 통과 후 실행 설정 해석이 실패하는 현상을 재현했다. HTTP 회귀 테스트에서 프로필별 설정 충돌의 저장 차단, 충돌 위치 표시, 규칙 수정 후 저장을 확인했다. Windows Chrome에서 Vault 규칙의 추가·수정·삭제를 확인했고, 의존성을 실행한 채로 Windows 런처를 종료·재실행하는 테스트도 통과했다. Windows 회귀 테스트는 Python 149개 통과, 선택 통합 테스트 8개 생략, JavaScript 8개 통과였다.

## 재개 지점

환경 변수·JVM·Spring의 프로필별 설정은 JSON 편집기를 사용한다. 폼을 확장할 때 macOS의 업무용 Registry로 사용 흐름을 확인한다.
