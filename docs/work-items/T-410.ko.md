# T-410 · 웹에서 저장된 검증 증거 다시 열기

**[English](T-410.md)** · 한국어 · [작업 인덱스](../index.ko.md)

## 설계

불러온 기준 프로젝트의 최근 검증 기록을 표시한다. 데스크톱 대시보드에서 이전 스위트와 각 시나리오의 증거를 다시 연다. 기존 보고서 파일을 사용해 서버 재시작 뒤에도 결과를 확인한다.

- 현재 실행 상태와 선택한 과거 보고서를 각각 표시한다.
- 실행 ID와 시나리오 번호로 조회한다. 증거 폴더 아래 해당 프로젝트의 보고서만 읽는다.
- 실패가 발생한 워크트리, 사유, 차이를 보여 준다. 증거가 없는 항목도 표시한다.

## 개발

- 스위트 보고서가 두 워크트리 경로를 저장한다. 기존 웹 보고서의 기준 경로는 [조회 코드](../../verifier/suite_evidence.py)가 첫 시나리오 비교 기록에서 찾는다. 같은 기준 프로젝트의 최근 실행 20개를 제공하며 생성한 실행 ID와 지정된 시나리오 보고서로만 접근한다.
- [대시보드](../../injector_core/web/index.html)에서 현재 작업과 저장된 기록을 각각 확인한다. 시나리오별로 달라진 값과 양쪽 관측 JSON을 나란히 볼 수 있다. 큰 정수의 정밀도를 유지하기 위해 표시할 값은 서버에서 문자열로 만든다.

## 검증

- Windows 데스크톱 Chrome에서 하위 서비스에 전달된 요청값의 차이를 재현했다. 웹 서버를 재시작한 뒤 같은 실패와 양쪽 값을 다시 열었다.
- 웹 API 테스트에서 로컬 토큰, 기준 프로젝트 범위, 경로 이탈 시도, 증거 없는 시나리오, 기존 보고서, 큰 정수의 정밀도를 검증한다.
- Windows에서 Spring Boot 프로브를 포함해 Python 회귀 테스트 145개가 통과했다. 선택 실행 항목인 Shop 및 WireMock 통합 테스트 8개는 건너뛰었다. 대시보드 JavaScript 테스트 8개가 모두 통과했다.

## 재개 지점

등록된 업무 프로젝트에서 증거를 확인한다. 런타임 결과 분류는 [T-380](T-380.ko.md)에서 이어간다.
