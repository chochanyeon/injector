# T-120. IDE 실행 전 자동 준비

[English](T-120.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-110, 결정 D-01

## 1. 설계

IntelliJ Application 실행 구성의 Before Launch에 내장 로컬 External Tool을 추가하는 경로를 지원한다. 사용자가 실행 구성마다 한 번 등록한다. 준비가 끝날 때까지 기다리고 실패를 종료 코드로 전달한다. 가져온 앱 설정은 생성 시점의 값과 일치해야 한다. [IntelliJ External Tools](https://www.jetbrains.com/help/idea/configuring-third-party-tools.html)

## 2. 개발

`ide-tool`은 XML과 필요한 Spring YAML을 생성하고 IDE 도구 입력값을 출력한다. 의존성은 IDE에서 도구를 실행할 때 준비한다. 이때 설정의 지문을 확인하고 기존 실행 구성을 덮어쓰지 않는다. 같은 계획의 소유 자원이 준비 상태라면 세션을 재사용한다. 관리 노드의 설정에 외부 환경 참조가 있으면 매번 준비한다. Compose 검사와 실행은 모두 선택한 소스 폴더를 작업 디렉터리로 사용한다.

## 3. 검증

Windows에서 생성 명령의 별도 프로세스 실행, 준비된 세션 재사용, 앱 설정 변경 시 실패 코드, 중단 시 정리를 검증했다. 설치된 IntelliJ IDEA 2025.3.3의 실행 전 도구는 성공에 종료 코드 0을 요구한다. macOS와 Windows IDE에서 실제 Run·Debug 조작은 별도 확인이 필요하다.

실제 Compose로 하위 폴더의 Compose 파일이 선택한 소스 루트의 `.env`를 읽는 것을 확인했다.

## 4. 재개 지점

등록한 업무 프로젝트의 실행 구성에 도구를 연결해 macOS IDE에서 Run, Debug, 취소를 확인한다. 강제 중단 후에는 `stop`으로 정리한다.
