## 1. Design

List individual app or infrastructure files in `nodeFiles`. Each contains one ID, variant definitions, dependencies, runners, and injection settings. Keep targets, variant selections, defaults, and hostnames in the root. Apply shared defaults, variant settings, `profileOverrides.<profile>`, then existing root overrides. Support inline and split files in schemas 1.0 and 1.1. Execution paths stay relative to source. With [T-200](T-200.md), `nodeFiles` resolve relative to the registry directory.

The editor opens existing registered nodes, validates the combined model, and saves the selected file.

## 2. Development

The [loader](../../injector_core/registry.py) combines validated files and rejects escapes, missing files, and duplicate nodes. The [editor](../../injector_core/web/app.js) switches files, keeps revisions, and identifies errors in other files. Migrated the [demo](../../examples/demo/registry.json) and updated the [registration guide](../../skills/injector-register-monorepo/references/runtime-registry-guide.md).

## 3. Verification

Both demo profiles kept the same plan and final environment, JVM, and Spring settings after splitting. Windows passed 111 tests including Spring Boot and Vault. Regression tests covered mixed files, overrides, bad paths, repair, and file conflicts. A temporary runtime verified dependency order and profile environment through HTTP. JavaScript and DOM checked switching, draft preservation, file-only saves, and reopening.
