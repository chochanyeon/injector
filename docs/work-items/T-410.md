# T-410 · Reopen saved verification evidence from the dashboard

**English** · [한국어](T-410.ko.md) · [Work index](../index.md)

## Design

Show recent saved runs for the loaded baseline project. Let the desktop dashboard reopen the suite and inspect the evidence for each scenario. Use the existing report files so results remain available after the web server restarts.

- Keep the latest live job separate from the selected saved report.
- Allow access by run ID and case number. Limit reads to that project's known report files under the evidence directory.
- Show the side, reason, and differences for a failure, and label cases with missing evidence.

## Development

- The suite report records the two checkout paths. The [reader](../../verifier/suite_evidence.py) can recover the baseline from the first comparison for older web reports. It returns up to 20 runs per loaded baseline and accepts only generated run IDs and known case files.
- The [dashboard](../../injector_core/web/index.html) reopens saved runs separately from the live job. The case view shows changed values and side-by-side observation JSON. Values are formatted on the server to preserve large integers.

## Verification

- Windows desktop Chrome reproduced a downstream request change, then reopened the failure and its original values after restarting the web server.
- The web API tests cover local token enforcement, project scope, run ID traversal, cases without reports, older reports, and exact large numbers.
- Windows regression run with the Spring Boot probe passed 145 Python tests. Eight optional Shop and WireMock integration cases were skipped. All eight dashboard JavaScript tests passed.
