# T-390 · 전체 테스트 환경 준비 및 실행

**[English](T-390.md)** · 한국어 · [작업 인덱스](../index.ko.md)

## 설계

입력 대기 없는 명령 하나로 예제를 빌드하고 실제 의존성을 기동해 Python, 브라우저 JavaScript, Verifier JVM 테스트를 실행한다. 선택 실행 Python 통합 테스트를 모두 활성화하고 쇼핑몰 수정 스위트도 CLI로 실행한다. 지원 플랫폼에서 Python 테스트가 하나라도 건너뛰어지면 전체를 통과로 판정하지 않는다. 진행 로그, 종료 코드와 증거 파일 링크를 보관한다. 임시 자원은 실행 단위로 구분하고 테스트가 끝나면 정리한다.

## 개발

- 표준 라이브러리만 사용해 시작할 수 있는 [환경 실행기](../../verifier/verify_environment.py)를 추가했다. 새 Python 가상환경을 만들고 버전이 고정된 의존성을 설치한다. Spring 프로브와 쇼핑몰 배포본을 빌드하고, 동적으로 할당된 루프백 포트에서 WireMock Vault를 기동한다.
- 실제 연동 옵션이 모두 켜진 Python 테스트, Node.js 테스트, JVM의 기록·비교 모드, Verifier Git 워크트리 통합 스크립트를 호출한다. 단계별 로그와 버전 있는 JSON 결과를 남긴다.
- `injector.py`를 통해 실제 쇼핑몰 수정 스위트를 실행하는 통합 테스트를 추가했다. 환경 실행기로 실행하면 시나리오 두 개와 워크트리 관측 네 개를 보관한다. 기존 쇼핑몰 테스트와 같은 포트 격리와 자원 정리를 사용한다.
- macOS에서는 CI와 같은 [실행기 검사](../../tests/check_macos_launcher.sh)를 사용한다.
- Windows Job을 종료한 뒤 기록한 프로세스까지 대기하도록 [런타임 정리](../../injector_core/runtime.py)를 수정했다. Python 가상환경의 런처가 Job 밖에 남아 자식 프로세스 종료를 기다릴 수 있다.

## 검증

- Windows 사전 점검에서 실행 파일이 없으면 실패 보고서를 남기고, 기존 출력 폴더는 보존하는 것을 확인했다.
- 빌드 결과가 없는 소스에서 Spring Boot와 쇼핑몰 배포본을 빌드했다. 소스 경로와 Maven 경로에 모두 공백이 있었다.
- 새 Windows 가상환경에서 IntelliJ 세션을 종료한 뒤 작업 폴더 잠금이 남는 문제를 재현했다. 수정 후 같은 환경에서 기존 테스트가 세 번 연속 통과했다.
- 기존 빌드 결과가 없는 새 Windows Git 체크아웃에서 명령을 실행했다. 모든 13단계가 통과했고 종료 코드는 0이었다. Python 테스트 150개, Node.js 테스트 6개, 기록·비교 모드의 JVM 테스트 7개, Git 워크트리 통합 사례 6개를 포함한다. 최종 Windows 실행에서 건너뛴 테스트는 0개다.
- 실제 쇼핑몰 스위트에서 버그 수정과 잘못된 주문의 회귀 검사가 통과했고 관측 파일 네 개를 보관했다. 임시 컨테이너와 네트워크가 정리된 것을 확인했다.
- macOS 실행기 검사 스크립트는 셸 문법을 확인했다. macOS 장비에서의 전체 환경 실행은 남아 있다.

## 재개 지점

전체 검증에는 `python verifier/verify_environment.py`를 사용한다. 같은 명령을 macOS 장비에서도 확인한다. 등록된 대상 프로젝트를 자동화할 때는 [T-380](T-380.ko.md)을 참고한다.
