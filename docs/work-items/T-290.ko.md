# T-290. 쇼핑몰 전체 서비스의 Vault 설정

[English](T-290.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-280

## 설계

쇼핑몰 애플리케이션 여섯 개에 각자의 Vault 경로와 시작 의존성을 둔다. Pricing은 두 실행 방식 모두 요청을 받기 전에 Vault 설정을 읽는다. 두 프로필에서 서비스 여섯 개의 조회를 확인하고, Vault의 모의 가격을 변경하면 주문 합계도 바뀌는지 검증한다.

## 개발

Storefront는 Vault에서 읽은 Redis 카운터 키를 사용한다. Inventory와 Java Pricing은 Vault에서 DB 사용자 이름을 읽는다. Pricing 대역은 WireMock이 시작하기 전에 Compose 네트워크로 Vault 설정을 읽고 `mockUnitCents`를 응답 가격에 반영한다. 각 애플리케이션의 레지스트리 파일에 `vault-mock` 직접 의존성을 둔다.

## 검증

- Windows에서 레지스트리 검증, 두 프로필의 실행 계획, `installDist` 빌드가 통과했다.
- `test_shop_demo.py` 통합 테스트에서 두 프로필 모두 시작 직후 Vault 요청 기록에 여섯 서비스 경로가 있는지 확인했다. 테스트 설정으로 대역 가격을 999센트에서 1,149센트로 바꾸자 주문 합계와 HTTP 기록에 반영됐다. Redis에서 Storefront의 수정된 카운터 키도 확인했다.
- 기본 Python 테스트 129개가 통과했고 별도 실행이 필요한 7개는 건너뛰었다. 실제 연동 검증은 Windows에서 Docker Desktop으로 진행했다.
