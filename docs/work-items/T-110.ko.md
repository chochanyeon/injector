# T-110. 다중 앱 통합 검증

[English](T-110.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업: T-060~T-100

| 설계 | 개발 | 검증 |
|---|---|---|
| 초안 | 미착수 | 미수행 |

## 1. 설계

- 산출물: `examples/` 아래 분리된 다중 앱 데모와 최신 검증 기록.
- 완료 기준: 공통 DB를 쓰는 앱, 다른 앱의 API 의존성, 모의 대체, 사용자 정의 호스트, 실패 경로를 한 흐름으로 재현한다. 도구 코드를 바꾸지 않고 두 프로젝트 구성을 선택한다.

상세 설계·선택지·결정 이유는 이 절에 이어서 기록한다. 공통 요구사항은 [전체 설계](../design.ko.md)를 참조한다. 현재는 작업 범위를 정한 초안이며 구현 설계가 완료된 상태는 아니다.

## 2. 개발

상태: 미착수. 이 작업의 구현 변경은 아직 없다.

설계에서 정한 산출물을 구현한 뒤 변경 파일·핵심 동작·남은 내용을 여기에 기록한다. 스키마·문서가 산출물인 작업은 그 파일과 작성 결과를 개발 산출물로 기록한다. 설계 절 작성만으로 개발 완료로 표시하지 않는다.

## 3. 검증

상태: 미수행. 아래는 수행할 검증이며 통과한 결과가 아니다.

- 검증: 깨끗한 환경에서 재현 절차를 따라 기동·디버그·전환·정리를 수행하고 실제 결과와 제한을 이 문서의 검증 절에 기록한다. 업무 모노레포가 없으면 범용성이 실제 업무에서 검증되었다고 표현하지 않는다.

검증 후 실제 명령·환경·관찰 결과·통과 여부·미검증 범위를 이 절에 남긴다. 실패하면 재현 방법과 남은 문제를 기록한다.

## 4. 재개 지점

- 다음 조치: 위 산출물과 완료 기준을 바탕으로 필요한 구체 설계를 확정하고 근거를 기록한다.
- 진행 중 변경: 없음.
- 완료 처리: 위 완료 기준과 검증 근거를 확인한 뒤 인덱스의 설계·개발·검증 상태를 함께 갱신한다.
