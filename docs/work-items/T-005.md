## 1. 설계

LLM이 모노레포에서 앱·접속점·호스트·포트·주입 키·전이적 의존성을 조사하고, 근거와 미확인 사항을 포함한 등록 초안을 작성하도록 돕는다. 파일·줄 근거, 추론, 로컬 변경 제안을 구분하고 비밀값은 복사하지 않는다.

등록 초안은 실행용 설정과 분리한다. 조사 작업 자체가 앱 실행·hosts/DNS 변경·실제 등록 적용을 수행하는 것은 아니다. 실행용 변환은 T-100으로 분리했다.

## 2. 개발

- [SKILL.md](../../skills/injector-register-monorepo/SKILL.md): 조사 작업의 범위·절차·완료 기준.
- [등록 프로토콜](../../skills/injector-register-monorepo/references/registration-protocol.md): 입력·산출물·근거·그래프 검토 규칙.
- [예시 JSON](../../skills/injector-register-monorepo/assets/registration-draft.example.json): 초안 형식 v0.1.

구현 근거: `db2246a`. 저장소 원본과 로컬 설치 사본을 구분한다. 현재 CLI는 초안 JSON을 읽지 않는다.

## 3. 검증

2026-11-16에 스킬 형식 검사, 예시 JSON 파싱, 노드·접속점·주입 참조 및 근거 필드 JSON Pointer의 유효성을 확인했다. 실제 업무 모노레포를 조사하는 행동 검증은 미수행이다. 따라서 완료 범위는 문서·형식·참조 검사에 한정한다.

## 4. 재개 지점

실제 등록에 연결할 때 T-100에서 변환 기능과 스킬을 함께 갱신한다. 현재 조사에 사용하려면 대상 모노레포와 앱·프로필을 지정하고 SKILL.md를 따른다.

T-140에서 검토된 실행용 registry를 AI가 직접 작성·수정할 관리 가이드를 추가했다. 자동 초안 변환 엔진은 여전히 T-100의 미구현 범위다.
