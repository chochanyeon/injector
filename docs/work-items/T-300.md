# T-300. Review fixes for execution and comparison

**English** · [한국어](T-300.ko.md)

[Work index](../index.md) · Prerequisites T-260 and T-290

## Design

Use one runtime identity for the default registry and recover older sessions. Check Compose host ports before startup. Preserve bounded local diagnostics when a managed process exits. Compare explicitly selected query values and apply JSON Pointer exclusions to original array indexes.

Acceptance requires regression tests for all five review findings and a live check with the shop demo.

## Development

- Explicit and implicit references to the source's default registry share one runtime lock and session. Stop also locates the legacy partitioned session. Explicit IDE artifact paths stay compatible with existing configurations.
- Execution checks reconcile each registered host port and transport with the selected Compose service. Managed process exit reports identify the node and link to up to 64 KiB of local output.
- Observations accept a `requestQuery` allowlist and report incomplete coverage when a call has a query and no policy. Verifier applies array exclusions in original index order and removes duplicates.

## Verification

- Windows runtime and HTTP observation regressions passed. A temporary Docker Compose configuration rejected the wrong published port in both check and prepare and accepted the matching port. The live shop demo passed in `real` and `mock`.
- The Node web tests, Verifier mechanics tests, and Spring baseline recording and comparison passed. A Linux container verified the POSIX runner's diagnostic tail and file permissions. Native macOS execution was outside this verification environment.
- The default Python suite passed 133 tests with seven opt-in tests skipped. All three demo registries validated.
