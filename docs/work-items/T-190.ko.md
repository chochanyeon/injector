## 1. 설계

- 프로젝트 루트 `registry.json`은 `nodeFiles`에 프로젝트 상대경로를 명시한다. 파일 하나에는 노드 하나의 ID, variant, 실행 정의, 의존성, 주입 설정을 둔다. 프로필의 실행 대상과 variant 선택, 공통 기본값, 호스트 매핑은 루트에 남긴다.
- 앱이 프로필마다 별도 값을 필요로 하면 해당 노드 파일의 `profileOverrides.<프로필>`에 둔다. 설정 합성 순서는 공통 기본값 → variant → 노드의 프로필 설정 → 기존 루트의 프로필 override다.
- 기존 1.0과 1.1 단일 파일을 지원한다. 한 registry에서 인라인 노드와 분리 파일을 함께 등록해 단계적으로 이전할 수 있다. 실행 정의에 있는 경로는 노드 파일의 위치와 무관하게 프로젝트 루트 기준이다.
- [T-200](T-200.ko.md)에서 registry를 소스 밖에 둘 수 있게 했다. 이 경우 `nodeFiles`는 registry 폴더를 기준으로 읽는다.
- 편집기는 명시적으로 등록된 기존 노드 파일만 열고 저장한다. 루트와 모든 노드를 조합해 검증하고, 선택한 파일에만 저장을 적용한다.

## 2. 개발

- [로더](../../injector_core/registry.py)가 분리 파일을 검증한 뒤 인라인 노드와 같은 그래프에 합친다. 프로젝트 밖 경로, 누락 파일과 중복 노드를 거부한다.
- [웹 편집기](../../injector_core/web/app.js)에서 설정 파일을 전환하고 각 파일의 원문과 편집 버전을 관리한다. 다른 파일에 문제가 있으면 파일 이름을 오류에 표시한다.
- [데모](../../examples/demo/registry.json)를 노드별 파일로 전환하고, [등록 스킬 가이드](../../skills/injector-register-monorepo/references/runtime-registry-guide.ko.md)에 경로와 설정 규칙을 반영했다.

## 3. 검증

- 데모 분리 전후 두 프로필의 실행 계획과 전체 노드의 최종 환경 변수·JVM 인자·Spring 설정을 비교했다.
- Windows에서 Spring Boot와 WireMock Vault를 포함한 전체 테스트 111개를 통과했다. 새 회귀 테스트는 기존 인라인 노드와 분리 노드 조합, 프로필 덮어쓰기, 잘못된 경로·파일 오류, 손상된 앱 파일 복구, 파일별 변경 충돌을 확인한다.
- 임시 프로젝트에서 분리된 노드 파일로 의존 서비스와 대상 프로세스를 순서대로 실행했다. 대상 HTTP 응답에서 앱 파일의 프로필별 환경 변수 값을 확인했다.
- JavaScript 구문 검사와 DOM 테스트 대역에서 파일 전환, 초안 유지, 개별 파일 저장, 편집기 접기 후 재열기를 확인했다.

## 4. 재개 지점

실제 모노레포를 등록할 때 노드별 파일 구조를 적용하고 T-090에 기록한 IntelliJ Debug 흐름을 검증한다.
