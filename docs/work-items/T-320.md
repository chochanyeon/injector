# T-320. Check registry execution requirements from the CLI

**English** · [한국어](T-320.ko.md)

[Work index](../index.md) · Prerequisites T-220 and T-300

## Design

Expose the browser's execution check as a CLI command for initial registration and automation. Use the same runtime validation, including variant overrides and central registry files. Success returns the execution order and applicable IntelliJ metadata. Failure identifies the first blocker.

Acceptance requires success with a reviewed registry, failure for a broken selected variant, and verification that both paths leave service and file state untouched.

## Development

`injector.py check` calls the same `check_requirements` function as the browser. It accepts the app, source checkout, optional central registry, profile, and variant overrides. The README and registration guides document its place between planning and preparation.

## Verification

- The Windows CLI regression confirmed an IntelliJ target and checked that a broken process variant returned exit 1 without creating session files or run configurations. It used an external registry with a custom extension.
- With the real Docker Compose CLI, the check accepted the demo's IntelliJ target and the shop's `real` profile with the Pricing WireMock override. The installed English and Korean guide copies matched the updated repository files.
- The default Python suite passed 136 tests with seven opt-in tests skipped. Live checks used Windows.

## Resume point

Use `check` during onboarding before the first `prepare` run. Validate startup against the real target after resolving any reported blocker.
