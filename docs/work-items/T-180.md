# T-180. registry 기반 의존성 그래프

[작업 인덱스](../index.md) · 선행: T-040, T-150, T-170

## 1. 설계

현재 선택한 프로필의 앱과 의존성 구조를 시각화한다. 전체 보기의 출발점은 그 프로필에서 variant가 선택된 모든 앱이다. 앱을 지정하면 그 앱에서 도달하는 하위 그래프를 표시한다. 선택한 variant, 실행 방식, 앱과 인프라 구분을 노드에 표시한다.

화살표는 소비자에서 직접 의존성으로 향한다. 여러 경로의 공통 노드는 하나로 그린다. 실제 준비 단계는 기존 실행 계획에 표시한다. 검증되지 않는 그래프는 오류를 표시한다.

## 2. 개발

- `GET /api/graph`는 기존 registry 검증과 DFS 계획을 재사용한다. 노드와 간선 메타데이터만 반환한다.
- 그래프는 HTML 노드와 Canvas 화살표를 사용한다. 같은 노드에 들어오는 경로와 중간 열을 건너는 화살표를 표시한다. 가로·세로 스크롤과 텍스트 목록을 제공한다.
- 전체 보기에서 앱을 클릭하거나 필터에서 앱을 선택할 수 있다. 실행 대상 선택은 그대로 유지한다. 프로필 변경과 registry 저장은 그래프를 갱신한다.

## 3. 검증

- 서버 테스트에서 전체·개별 앱 조회, 프로필에 선택되지 않은 앱 제외, 공유 의존성 단일 포함, 값 비노출, dummy/real variant 반영을 확인했다.
- Node에서 DOM과 Canvas 테스트 대역을 실제 로컬 서버에 연결했다. 전체 보기의 세 노드·세 화살표, Catalog 집중 보기, Redis 공유, dummy→real 전환을 확인했다.
- 변경 커밋 `828909d`의 macOS 15 ARM64와 Windows 2025 x64 CI가 모두 통과했다. 각 OS에서 95개 통과, 외부 통합 6개 건너뜀. [CI 실행 결과](https://github.com/chochanyeon/injector/actions/runs/44192310665)
- 브라우저 제어 호스트가 연결되지 않아 브라우저에서의 실제 배치와 스크롤은 직접 확인하지 못했다.

## 4. 재개 지점

브라우저에서 작은 화면, 긴 앱 이름, 서로 교차하는 간선이 많은 registry를 확인한다. 다음 개발은 T-080이다.
