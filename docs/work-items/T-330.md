# T-330. Compare a correlated HTTP and Kafka trace

**English** · [한국어](T-330.ko.md)

[Work index](../index.md) · Prerequisites T-280 and T-310

## Design

Use the shop's loopback Loki instance to collect HTTP and Kafka events for a single scenario request ID. Compare the selected target fields and normalized event counts across two worktrees. Require declared events to be present before reporting a conclusive result.

Acceptance covers equivalent traces, a downstream change with an unchanged response, and a missing Kafka consumer event.

## Development

- Version 2 scenarios declare a Loki endpoint, stream app label, time limit, and required events. The existing observation commands send a unique request ID and capture the selected response fields and the correlated events before stopping the session.
- The shop records caller, dependency, method, route, and status for outbound HTTP. Kafka publish and consume logs include the topic. Verifier compares event multisets and classifies missing required events as incomplete.
- The CLI and web comparison accept both recording formats. The trace keeps the selected HTTP and Kafka metadata and omits request IDs and timestamps from artifacts.

## Verification

- The Windows CLI returned `PASS` on two actual Git worktrees with ten correlated events on each side. Both sessions stopped.
- On Windows, Docker and the shop's `mock` profile verified a changed Kafka topic with an unchanged checkout response and an unobserved Kafka consumer resulting in `INCONCLUSIVE`. The existing shop integration also passed in `real` and `mock`, including version 1 quote recording.
- The default Python suite passed 137 tests with eight opt-in tests skipped. The Node browser logic suite passed six tests, and the live loopback web endpoint compared version 2 artifacts.
