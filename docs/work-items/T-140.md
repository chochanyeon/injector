## 1. Design

Related to R-14. Keep JVM flags and `System.getProperty` values on the JVM while supplying Spring settings through external YAML. Add schema 1.1, `springProperties`, and the `springProperty` injection channel. Version 1.0 remains supported. Preserve scalar/list/map types and environment references and reject null. Later layers replace matching top-level keys. Detect overlapping paths, duplicate flattened keys, and environment or VM settings that shadow YAML leaves. Inherited settings, all relaxed binding aliases, and program arguments remain outside conflict analysis.

`render --project <root> --profile <name> --node <id>` generates Spring YAML and an IntelliJ XML with a file URI in `spring.config.additional-location`. Preserve source YAML and existing managed-path safety checks. Spring secrets become `${ENV_NAME}` placeholders. Environment and VM secret references that would be persisted to XML are rejected. Initial loading settings and active/default/include profiles belong in JVM properties or the environment. An existing additional location or opaque application JSON is reported as a conflict. Compose mounts and automatic startup remain separate.

The AI guide distinguishes draft discovery from reviewed edits. Trace consumers and file and line evidence, use the actual schema, preserve existing confirmed values, and leave unknowns in findings. Verify planned behavior separately from app startup.
