## 1. 설계

사용자 요청: 회사 Vault에 실제 연결하거나 Vault 이미지를 기동하는 대신, WireMock 컨테이너가 앱의 Vault 조회 요청에 맞는 로컬 설정값을 반환한다. 기존 계획의 T-050보다 이 요청을 우선 처리했으며 작업 ID는 새로 T-130을 부여했다.

### 1.1. 요청과 응답 계약

업무 앱의 실제 계약은 아직 제공되지 않았다. 최소 데모는 `GET /v1/secret/data/injector-demo`와 고정 로컬 `X-Vault-Token`을 사용한다. 응답은 [Vault KV v2 read API](https://developer.hashicorp.com/vault/api-docs/secret/kv/kv-v2)의 `data.data`와 `data.metadata` 형식을 따른다.

정상 요청은 200, 토큰 누락·불일치는 403, 올바른 토큰으로 요청한 미등록 /v1 경로·메서드·query는 404 JSON 오류다. 매핑 priority로 정상 응답 → 인증된 미지원 응답 → 토큰 오류를 선택한다. 고정 토큰 매칭은 실제 인증·권한 엔진이 아니다.

login·token lookup/renew·lease·KV v1·버전 query·쓰기·namespace·TLS는 미지원이다. 회사 SDK가 자동 호출하는 엔진 탐색·갱신 등을 포함한 호환성도 미검증이다. 요청 계약이 확보되면 필요한 매핑만 추가한다.

### 1.2. 설정과 실행 경계

독립 `vault-mock` 서비스를 사용하고 기존 Catalog용 WireMock과 매핑을 분리한다. 호스트 주소는 localhost:18083, 컨테이너 주소는 vault-mock:8080이다. `--with-vault`를 쓰는 기존 데모 up/generate/run/plan에만 대역 환경을 추가한다. 일반 등록 검사 명령에서 이 옵션을 받지 않는다.

원본 데모 설정의 vaultMock에는 서비스 이름·주소·VAULT_PATH·로컬 더미 토큰을 둔다. XML과 Docker 설정을 생성할 때 호출 위치에 맞는 VAULT_ADDR를 반영한다. fixture의 data.data에는 앱이 읽을 키·값을 둔다. 실제 회사 비밀값은 조회·기록하지 않는다.

기존 Java Main은 Vault API를 호출하지 않는다. 별도 Python 설정 소비 앱과 `vault-demo` 명령으로 조회·파싱·값 사용을 확인한다. 이 앱은 응답의 메시지·기능 플래그를 사용하며 자격증명 값 자체는 출력하지 않는다. 특정 프레임워크가 VAULT_ADDR 등을 자동 인식한다고 가정하지 않는다.

일반 런타임 스키마는 변경하지 않았다. Vault 대역은 장차 Compose 실행과 HTTP 접속점을 가진 일반 의존 노드로 표현하면 된다. 특별한 실제 Vault 비밀값 공급자를 구현하는 작업은 아니다. 일반 등록의 자동 기동 연결은 T-050 이후에 남긴다.

## 2. 개발

- [매핑·응답](../../examples/demo/docker/vault-mock/): 정상 조회·미등록·토큰 오류 및 로컬 KV v2 값.
- [Compose](../../examples/demo/docker/compose.yaml): WireMock 3.13.2 서비스, loopback 포트, read-only 파일 마운트·healthcheck.
- [원본 설정](../../examples/demo/config/project.json): 데모 전용 vaultMock 정의.
- [Injector CLI](../../injector.py): --with-vault의 선택적 기동·환경 생성, vault-demo 소비 앱 실행.
- [소비 앱](../../examples/demo/vault_client.py): KV v2 JSON 읽기·설정 사용, 오류 시 응답 본문·토큰 미출력.
- [사용 가이드](../../examples/demo/docker/vault-mock/README.ko.md): 앱별 경로·키·값 수정과 재기동 방법.
- [등록 프로토콜](../../skills/injector-register-monorepo/references/registration-protocol.ko.md): Vault 사용 방식·KV 버전·앱 요청 계약 조사 및 로컬 대체 지침.

기존 mock/real 데모는 --with-vault가 없으면 새 Vault 대역을 기동하지 않는다. 이미 실행 중인 대역을 자동 종료하는 정책은 추가하지 않았다.

## 3. 검증

2026-11-17, Docker 29.4.0 Linux 엔진에서 다음을 수행했다.

1. `python injector.py up --profile mock --with-vault`: WireMock·vault-mock healthcheck 통과.
2. INJECTOR_TEST_VAULT_URL을 `http://127.0.0.1:18083`으로 설정하고 `python -m unittest discover -s tests -q`: 총 58개 통과. 이 중 WireMock 통합 검증은 4개다.
3. `python injector.py vault-demo`: API에서 받은 메시지와 databaseConfigured=true 출력. 비밀번호 값 자체는 출력하지 않음.
4. Compose exec로 vault-mock 컨테이너에서 `http://vault-mock:8080/v1/secret/data/injector-demo` 조회 성공.
5. Compose config 검증 통과.

통합 검증에서 실제 KV v2 매핑 값, 토큰 누락·오류 403, 미등록 경로·버전 query·쓰기 요청 404, 별도 앱의 응답 소비를 확인했다. 단위 검증은 데이터에 따른 기능 플래그 동작, KV v2 파싱·헤더, 오류 시 토큰 미노출, opt-in 환경 생성·서비스 선택을 포함한다.

WireMock URL을 지정하지 않는 기본 테스트 실행은 54개가 수행되고 통합 4개는 skip된다. Java 컴파일·IntelliJ Debug·실제 회사 앱/SDK는 이번 작업에서 다시 검증하지 않았다. 사용 중인 실제 Vault와 동등한 모든 기능을 제공한다는 결과가 아니다.
