# T-380 · Run registration and verification without manual prompts

**English** · [한국어](T-380.ko.md) · [Work index](../index.md)

## Design

An LLM can use a reviewed registry, scenario expectations, and checkout paths to complete a local verification run from the CLI. For a first registration, it uses source evidence and reports missing settings or decisions for review. Routine runs use the approved inputs to preflight, prepare the app and dependencies, reproduce the failure, verify the candidate and related behavior, and clean up. The web UI uses the same validation and execution paths.

- Preflight checks all cases before starting any app. It returns structured diagnostics that identify the affected case or node and the missing input or failed check.
- Normal execution returns a versioned result with a verdict, exit code, saved evidence paths, and separate details for input, startup, behavior, and cleanup failures. An LLM can select the next action from the result.
- A fresh agent can use documented prerequisites to run a registered target project and produce the verification report without UI interaction. Business expectations and required secrets come from reviewed inputs.

## Development

- [Suite planning](../../verifier/worktree_suite.py) checks both worktrees and all declared cases. `check-suite` returns a version 1 JSON report with `READY` or `BLOCKED`, the corresponding exit code, and scoped diagnostics. `verify-suite` uses the same preflight and returns that report when preflight blocks execution.
- [Injector](../../injector_core/runtime.py) checks active sessions, required settings, host resolution, Compose configuration and engine, and occupied ports without creating runtime files. It checks session and launch conditions again at execution. A missing environment reference reports the variable name only.
- An LLM can use the declared scenario index, worktree side, and node to locate a blocker. Preparation still depends on the target project's build and fixture setup. [Registration workflow](T-340.md) · [Suite execution](T-360.md) · [Verifier workflow](../../verifier/README.md#run-a-suite)

## Verification

- Windows process tests verified a ready suite, a later invalid fix check, identical blocked reports from `check-suite` and `verify-suite`, and independent environment and port blockers on the two worktrees. The report did not include resolved settings. The check did not write runtime or output files.
- Windows passed 143 regression tests, including Spring Boot. Eight opt-in tests were skipped in that run. A separate live Docker and JVM run passed the two-case shop suite through the CLI and confirmed that the shared preflight permits a valid execution.

## Resume point

Give startup, observation, and cleanup failures distinct machine-readable results. Verify the CLI in a registered work monorepo and on macOS.
