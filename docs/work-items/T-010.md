# T-010. 실행용 앱 등록 스키마

[작업 인덱스](../index.md) · 선행 작업: 없음

| 설계 | 개발 | 검증 |
|---|---|---|
| 초안 | 미착수 | 미수행 |

## 1. 설계

- 관련: R-08~R-11, 설계 15~16절, D-02~D-07.
- 시작: 현재 데모 설정과 LLM 등록 프로토콜을 비교해 실행에 필요한 정보와 조사용 정보를 분리한다.
- 산출물: 이 문서의 설계 절에 버전, 앱 ID, 프로젝트 경로, 실행 모드, 접속점, 이름 해석, 의존 간선, 주입 참조, 준비 기준을 정의한다. 런타임 형식과 예시는 이 작업에서 결정한다.
- 완료 기준: 두 앱이 공통 인프라를 참조하는 다단계 예시와 실제·모의 대체 선택을 표현한다. 필수값·기본값·비밀값 참조·알 수 없는 값 처리·기존 POC 호환 범위를 명시한다.

상세 설계·선택지·결정 이유는 이 절에 이어서 기록한다. 공통 요구사항은 [전체 설계](../design.md)를 참조한다. 현재는 작업 범위를 정한 초안이며 구현 설계가 완료된 상태는 아니다.

## 2. 개발

상태: 미착수. 이 작업의 구현 변경은 아직 없다.

설계에서 정한 산출물을 구현한 뒤 변경 파일·핵심 동작·남은 내용을 여기에 기록한다. 스키마·문서가 산출물인 작업은 그 파일과 작성 결과를 개발 산출물로 기록한다. 설계 절 작성만으로 개발 완료로 표시하지 않는다.

## 3. 검증

상태: 미수행. 아래는 수행할 검증이며 통과한 결과가 아니다.

- 검증: 각 필드의 출처와 사용처를 설명하고, 순환·누락 참조·충돌 예시를 표현할 수 있는지 검토한다. 구현을 시작하기 전에 미결정 선택의 이유를 기록한다.

검증 후 실제 명령·환경·관찰 결과·통과 여부·미검증 범위를 이 절에 남긴다. 실패하면 재현 방법과 남은 문제를 기록한다.

## 4. 재개 지점

- 다음 조치: 현재 데모 설정과 LLM 등록 프로토콜을 비교해 실행에 필요한 정보와 조사용 정보를 분리한다.
- 진행 중 변경: 없음.
- 완료 처리: 위 완료 기준과 검증 근거를 확인한 뒤 인덱스의 설계·개발·검증 상태를 함께 갱신한다.
