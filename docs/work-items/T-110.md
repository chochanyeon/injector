## 1. Design

Use a self-contained fixture under `examples/demo/multi-app/`. Exercise two apps sharing SQLite, an injected cross-app HTTP address, a mock variant, a custom hostname disagreement, and startup rollback. Use two temporary source checkouts and reviewed registry candidates without editing Injector code. The existing Docker and JVM demo provides a separate environment check. [Design](../design.md)

## 2. Development

`tests/test_multi_app_integration.py` converts drafts into external registries, starts the services with the production runtime, calls the target, and checks cleanup and data retention.

## 3. Verification

Both Windows integration tests passed. The real scenario observed writes from both applications in one SQLite database. The alternate checkout called the mock. A failed catalog start rolled back the prepared database service and retained its data. The custom alias test supplies a resolver response for a different address and confirms that preparation stops before launching anything.

A separate Windows smoke test copied the Java demo to a temporary checkout, allocated unused ports, and used an isolated Compose project. With the installed JDK executable, both Java targets called WireMock in dummy mode and the real Catalog in real mode. A SQL query inside PostgreSQL returned successfully. The test removed its Compose containers and network.

## 4. Resume point

Verify a custom hostname with a real resolver and Debug on a work project on macOS.
