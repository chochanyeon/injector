# T-160. macOS와 Windows 실행 환경 지원

[작업 인덱스](../index.md) · 선행: T-060, T-070, T-150

## 1. 설계

macOS를 주 사용 환경으로 두고 Windows에서도 같은 준비·종료·hosts 명령을 제공한다. 운영체제별 실행 파일은 공통 Python CLI를 열고, UI와 registry는 두 OS가 공유한다. Windows는 VBS로, macOS는 Finder에서 실행할 수 있는 `.command`로 시작한다. 두 실행 파일 모두 프로젝트의 `.venv`를 우선 사용한다.

macOS의 hosts 변경은 관리자 권한으로 명시적으로 실행한다. 변경본에 기존 소유권과 권한을 복사한 뒤 같은 파일시스템에서 교체한다. Windows는 기존 ReplaceFileW 방식을 사용한다. 양쪽 모두 잠금과 기존 항목 보존 정책을 공유한다.

## 2. 개발

- `Start-Injector.command`에 실행 권한과 LF를 지정한다. Finder에서 실행될 때 ARM·Intel Homebrew와 사용자 Docker CLI 경로를 찾는다.
- `hostnames.py`에서 macOS 잠금과 파일 적용·제거를 연결했다. 원본 속성 복사에는 macOS의 `cp -p`를 사용한다. [Apple cp 매뉴얼](https://github.com/apple-oss-distributions/file_cmds/blob/main/cp/cp.1)
- process 작업 폴더, Compose 파일, IntelliJ 프로젝트 폴더가 같은 프로젝트 경로 해석을 사용한다. POSIX 프로세스는 서버 터미널과 다른 세션에서 실행된다.
- 로컬 화면은 숫자 루프백 주소에 바인딩할 때 역방향 DNS를 조회하지 않는다.
- GitHub Actions가 최소 지원 Python 3.10에서 macOS ARM64와 Windows x64의 테스트를 실행한다. macOS에서는 공백이 포함된 경로에서도 시작 파일이 올바른 인터프리터와 인자로 실행되는지 확인한다.

## 3. 검증

- Windows에서 기본 테스트 96개 중 90개 통과, 외부 통합 6개 건너뜀.
- Windows의 Docker Desktop에서 dummy와 real 데모 준비 후 IntelliJ XML 생성 및 종료까지 확인했다.
- Git Bash에서 macOS 시작 파일의 문법과 공백이 있는 경로의 가상 환경 선택을 확인했다.
- Redis, WireMock, Temurin JDK·JRE, PostgreSQL, Kafka의 데모 버전이 모두 linux/arm64와 linux/amd64 이미지를 제공하는 것을 레지스트리 매니페스트에서 확인했다.
- macOS·Windows의 CI에는 임시 hosts 적용·복원과 포트·프로세스·IntelliJ 설정 생성 테스트가 포함된다. 실제 Finder·브라우저 UI·IntelliJ Debug와 시스템 hosts 관리자 적용은 수동 검증 범위다.
- 첫 macOS 실행에서 루프백 서버의 역방향 DNS 조회가 지연돼 테스트 앱의 준비 확인이 시간 초과됐다. 화면 서버와 런타임 테스트의 루프백 HTTP 서버에서 조회를 생략했다.
- 수정 커밋 `5b62cf7`의 CI가 macOS 15 ARM64와 Windows Server 2025 x64에서 모두 통과했다. 각 OS에서 90개 통과, 외부 통합 6개 건너뜀. macOS 시작 파일 테스트도 성공했다. [CI 실행 결과](https://github.com/chochanyeon/injector/actions/runs/44189484410)

## 4. 재개 지점

macOS에서 Finder로 화면 열기, dummy/real 준비, IntelliJ Debug, 종료 및 관리 권한의 hosts 적용·제거까지 확인한다. 기능 개발은 T-080에서 이어간다.
