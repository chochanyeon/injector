# T-180. registry 기반 의존성 그래프

[English](T-180.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행: T-040, T-150, T-170

## 1. 설계

현재 선택한 프로필의 앱과 의존성 구조를 시각화한다. 전체 보기의 출발점은 그 프로필에서 variant가 선택된 모든 앱이다. 앱을 지정하면 그 앱에서 도달하는 하위 그래프를 표시한다. 선택한 variant, 실행 방식, 앱과 인프라 구분을 노드에 표시한다.

화살표는 소비자에서 직접 의존성으로 향한다. 여러 경로의 공통 노드는 하나로 그린다. 실제 준비 단계는 기존 실행 계획에 표시한다. 검증되지 않는 그래프는 오류를 표시한다.

[Eclipse ELK의 계층 배치](https://eclipse.dev/elk/blog/posts/2025/25-08-21-layered.html)와 [React Flow의 간선 표시 예제](https://reactflow.dev/examples/edges/edge-types)를 참고했다. 현재 Canvas에서 노드를 단계별로 배치하고 선택한 노드의 직접 연결에 대비를 주는 방식으로 개선했다.

## 2. 개발

- `GET /api/graph`는 기존 registry 검증과 DFS 계획을 재사용한다. 노드와 간선 메타데이터만 반환한다.
- 그래프는 HTML 노드와 Canvas 화살표를 사용한다. 같은 노드에 들어오는 경로와 중간 열을 건너는 화살표를 표시한다. 가로·세로 스크롤과 텍스트 목록을 제공한다.
- 앱 필터는 하위 그래프를 표시한다. 노드를 클릭하면 배치를 유지한 채 직접 연결만 강조하고 의존 대상·사용하는 노드를 텍스트로 표시한다. 공유 노드로 들어오는 선은 끝점을 나눠서 그린다. 프로필 변경과 registry 저장은 그래프를 갱신한다.
- 의존성 그래프, 실행 순서, 진행 기록은 제목으로 접고 펼친다. 실행 순서를 접어도 준비 상태와 결과는 표시한다.
- 기본 데모에 두 번째 IntelliJ 대상인 `support-console`을 추가했다. 두 앱이 Catalog·Vault 대역을 공유하고, `real`에서만 Catalog에 PostgreSQL을 추가한다. 기존 Java 앱과 Docker 이미지를 재사용한다.

## 3. 검증

- 서버 테스트에서 전체·개별 앱 조회, 프로필에 선택되지 않은 앱 제외, 공유 의존성 단일 포함, 값 비노출, dummy/real variant 반영을 확인했다.
- Node에서 DOM과 Canvas 테스트 대역을 실제 로컬 서버에 연결했다. 전체 보기의 세 노드·세 화살표, Catalog 집중 보기, Redis 공유, dummy→real 전환을 확인했다.
- 변경 커밋 `828909d`의 macOS 15 ARM64와 Windows 2025 x64 CI가 모두 통과했다. 각 OS에서 95개 통과, 외부 통합 6개 건너뜀. [CI 실행 결과](https://github.com/chochanyeon/injector/actions/runs/44192310665)
- 그래프를 접으면 Canvas 그리기를 건너뛰고 다시 펼칠 때 화살표를 그리는 동작을 DOM·Canvas 테스트 대역으로 검증했다.
- 확장된 데모에서 그래프 API가 `dummy` 5개 노드·6개 연결, `real` 6개 노드·7개 연결을 반환했다. Windows Docker에서 `platform-service --mode dummy`를 준비해 실제 WireMock과 Vault KV 응답을 확인하고, `support-console --mode real`을 준비해 PostgreSQL readiness와 실제 Java Catalog 응답을 확인했다. 앱은 생성된 구성으로 JVM에서 실행했고 테스트용 세션을 종료했다.
- 실제 브라우저의 dummy 전체 보기에서 계층 제목과 연결선 배치를 확인했다. Catalog를 클릭해서 들어오는 앱 두 개와 나가는 Redis 연결이 강조되고 방향별 목록이 표시되는 것을 확인했다.

## 4. 재개 지점

브라우저에서 작은 화면, 긴 앱 이름, 서로 교차하는 간선이 많은 registry를 확인한다. 다음 개발은 T-080이다.
