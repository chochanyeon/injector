# T-200. 대상 워크트리와 registry 보관 위치 분리

[English](T-200.md) · **한국어**

[작업 인덱스](../index.ko.md) · 선행 작업 T-005, T-170, T-190

## 1. 설계

- 기본 보관 위치는 Injector의 Git 제외 폴더인 `registries/<레포-ID>/`다. 같은 레포의 워크트리는 설정을 공유한다. CLI `--project`는 소스 폴더를 가리킨다. `--registry`는 직접 선택한 파일 또는 기본 `registry.json`이 들어 있는 폴더를 받는다. 파일을 직접 지정하면 이름과 확장자에 관계없이 Registry JSON 내용을 검증한다.
- `nodeFiles`는 선택한 Registry 파일의 상위 폴더 기준이며, IDE·실행·Compose 파일의 경로는 소스 폴더 기준이다. 기존 소스 내 Registry도 지원한다.
- 외부 Registry 모드에서 Injector 생성물은 Registry 파일과 워크트리 조합별 경로에 저장한다. 기본 `registry.json`은 파일로 지정하거나 폴더로 지정해도 기존 세션 경로를 사용한다. IntelliJ는 결과의 실행 XML을 가져오는 방식으로 사용한다. 실행하는 앱이나 IDE의 자체 파일 쓰기는 각 도구에 따른다.

## 2. 개발

- 소스 선택기는 폴더를 고르고 Registry 선택기는 선택한 일반 파일의 경로를 반환한다. 화면은 그 경로로 불러오기와 편집을 수행한다. 기본 Registry가 있는 폴더를 직접 입력할 수도 있다. Registry 유효성은 불러오기 단계에서 확인한다.
- UI에서 소스와 Registry를 별도 지정하며 중앙 보관 폴더의 기본 Registry를 입력 후보로 제공한다. 편집기, 실행 계획, 그래프와 준비·종료 요청이 지정된 조합을 사용한다.
- 등록 스킬의 실행 설정과 조사 자료 기본 경로를 중앙 보관 위치로 바꿨다.

## 3. 검증

- HTTP 회귀 테스트는 registry 없는 워크트리 선택과 별도 registry를 사용하는 그래프·편집을 확인한다.
- 런타임 회귀 테스트는 의존성을 실제로 기동하고 종료하며 IntelliJ XML, Spring YAML과 세션 파일이 외부 registry 아래에만 생성되는지 확인한다.
- Windows에서 Spring Boot·Vault 통합을 포함한 전체 테스트 113개가 통과했다. 별도 경로로 CLI `validate`·`plan`·`stop`을 실행하고, 테스트 DOM에서 소스 선택 후 중앙 registry를 선택하는 흐름과 그래프·편집기 전달값을 확인했다.
- 저장소와 로컬 설치본의 등록 스킬 형식 검사와 변경 파일 해시 대조를 통과했다.
- 기존 파일 선택 테스트는 선택 취소와 Registry 불러오기·그래프·편집을 확인했다. 모의 호출로 Windows·macOS의 파일 및 폴더 선택 분기를 검사했다. 이름이 다른 파일의 회귀 검증에서는 스키마가 맞지 않는 내용의 거부, 지정한 파일 선택과 편집, 확장자가 없는 파일의 CLI 검증, 이름이 다른 Registry의 실행 파일 분리를 확인했다. Windows에서 Python 테스트 111개와 웹 테스트 3개가 통과했고 선택 실행 Python 테스트 6개를 건너뛰었다. 실제 데스크톱 조작은 추가 확인이 필요하다.

## 4. 재개 지점

업무 워크트리에서 OS 선택 창과 IntelliJ 실행 구성 가져오기·Debug 동작을 확인한다.
